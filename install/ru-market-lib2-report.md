## 1. Формат и почему именно он

Серверные сообщения dshmarket **двуязычные**: строки вида `'中文… / English…'` и объекты `{ zh, en }`.
Половину выбирает **клиент**, функция `pickBilingualPair` (`client.js`), а код языка там вычислялся
бинарно:

```js
const lang = String(localeSnap.active).toLowerCase().startsWith("zh") ? "zh" : "en";   // было
```

Следствия (проверено по коду):
* для локали `ru` `lang === "en"` → бралась **английская** половина (двуязычные сообщения);
* строка **без** разделителя `' / '` возвращалась **как есть** → одноязычные китайские сообщения
  показывались по-китайски даже русскому пользователю;
* сервер локаль не знает вообще (в `routes.js` нет чтения `Accept-Language`), поэтому решать на сервере нельзя.

**Принятый формат** (согласован тимлидом, един для меня и market-lib-ru):

```
'<中文> / <English> / <Русский>'        // часть 0 — китайская, часть 1 — английская, часть 2 — русская
```

Почему не проще: если просто заменить английскую половину русской, английская и японская локали
получат русский текст — регресс. Трёхчастный формат позволяет отдать каждой локали её половину:

| Локаль | Часть | Поведение |
|---|---|---|
| `zh` | 0 | китайская (как было) |
| `en`, `ja` | 1 | английская (как было) |
| `ru` | 2 | **русская (новое)** |
| любая другая | 1 | английская (как было) |

Строки без разделителя и строки иной формы ведут себя ровно как раньше.

### Правка механизма (`client\client.js`, единственная, разрешена тимлидом)

1. Реальный код локали вместо бинарного флага (одно место):
   ```js
   const activeLocale = String(localeSnap.active).toLowerCase().split("-")[0];
   const lang = ["zh", "en", "ja", "ru"].includes(activeLocale) ? activeLocale : "en";
   ```
   Все 30+ мест, где `lang` используется, проверены: для `ru` они ведут себя как «не-zh», а выборки
   описаний/категорий (`description[lang] || description.en`) безопасно падают на английский.
2. `pickBilingualPair` получил трёхчастную ветку:
   `parts.length === 3 && cjkCount(parts[0]) > 0 && cjkCount(parts[1]) === 0 && cjkCount(parts[2]) === 0`
   → `zh` → часть 0, `ru` → часть 2, иначе часть 1. Строки с двумя частями (и любые иные) идут по
   старой эвристике по CJK — поведение не изменилось.

## 6. Что слетит при обновлении

Любое обновление/переустановка `dshmarket` (`dsh plugin add`, обновление из маркета, `pnpm install`)
вернёт оригинальные `lib\*.js` и `client\client.js` — **весь перевод серверного слоя и словарь `ru`
пропадут**, рынок снова станет англо-китайским. `pnpm install` дополнительно вычищает каталоги в
`node_modules`, не объявленные в зависимостях профиля.
