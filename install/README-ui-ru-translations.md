## Главное: у dshmarket ЕСТЬ штатный i18n — не хватало только словаря `ru`

Клиентский бандл `client\client.js` содержит регион `src/client/locales.ts` с тремя словарями и
регистрирует их в штатном реестре локалей хоста:

| Что | Где (было) |
|---|---|
| `const zh = {…}` | строки 200–965 |
| `const en = {…}` | строки 966–1730 |
| `const ja = {…}` | строки 1731–2493 |
| `ctx.locale.register(NS, { zh, en, ja })`, `NS = "dsh-market"` | строка 17521 |

Словаря `ru` не было. Контракт хоста (`node_modules\dsh-locale-ru\lib\client.js`) объявляет язык как
`{"id":"ru","label":"Русский","fallback":"en"}` — поэтому при активной локали `ru` рынок уходил на
**английский fallback**. Это и есть причина жалобы «в маркете плагины на английском»: не «нет i18n»,
а отсутствующий `ru`-словарь. Никаких инлайновых подписей переводить было не нужно — весь видимый
текст клиента уже проходит через `t()`.

**Сделано:** добавлен `const ru = {…}` (762 ключа, строки 2501–3264) и он зарегистрирован:

```js
// client.js:18292
ctx.effect(() => ctx.locale.register(NS, {
    zh,
    en,
    ja,
    ru
}), "dsh-market: dictionaries");
```

Словари `zh` и `ja` **не тронуты** — они источник для китайской и японской локалей; их удаление
сломало бы эти языки.

**Зависимость:** словарь `ru` вступает в силу, когда в хосте активна локаль `ru`. Сам язык `ru`
регистрирует пакет `dsh-locale-ru` (`locale.addLanguage({id:"ru",fallback:"en"})`, задача task-1);
в `dshmarket` намеренно **не** добавлен свой `addLanguage`, чтобы не регистрировать один и тот же язык
дважды. Если `dsh-locale-ru` не установлен или неактивен, словарь `ru` просто не запрашивается —
это безвредно и ничего не ломает.

## Метрика CJK: почему наши числа расходились (сверено)

Числа зависят от набора диапазонов. Один и тот же файл:

| Метрика | До правок | После основного прохода | После добора (итог) |
|---|---|---|---|
| **Han + кана** `[\u3040-\u30FF\u3400-\u4DBF\u4E00-\u9FFF\uF900-\uFAFF]` — это и есть **23903** из разведки тимлида | **23903** | 23903 | **23942** |
| Моя метрика: CJK с пунктуацией, без каны `[\u3000-\u303F\u3400-\u4DBF\u4E00-\u9FFF\uF900-\uFAFF\uFF00-\uFFEF]` | 13669 | 13662 | **13675** |
| Только CJK-пунктуация и fullwidth `[\u3000-\u303F\uFF00-\uFFEF]` | 1662 | 1655 | 1658 |

Число 23903 воспроизведено точно: `Han+кана+punct(25565) − punct(1662) = 23903`.
Метрика тимлида (Han+кана) в основном проходе не менялась: вся эта масса лежит в словарях `zh` и `ja`
плюс регекспы, и удалять её нельзя — иначе сломаются китайская и японская локали. После добора она
выросла 23903 → 23942, потому что добор **добавил** китайское и японское значения нового ключа — это
аддитивное расширение словарей, а не остаток (см. «Добор» ниже). Пунктуация: 1662 → 1655 (основной
проход, −7) → 1658 (добор, +3).

Полная раскладка после правок (13 675 по моей метрике):

|---|---|---|
| Словарь `zh` (200–966) | 8670 | — |
| Словарь `ja` (1733–2500) | 4773 | — |
| Словарь `en` / `ru` | 0 | — |
| Вне словарей: комментарии | 90 | 17 |
| Вне словарей: регекспы под китайские данные вендора | 133 | 7 |

## Что слетит при обновлении плагина

* Любое обновление/переустановка `dshmarket` (`dsh plugin add dshmarket`, обновление из самого маркета,
  `pnpm install`) поставит оригинальный `client.js` — **словарь `ru` пропадёт**, рынок снова станет
  английским. Правку нужно применить заново.
* `pnpm install` вычищает каталоги в `node_modules`, не объявленные в зависимостях профиля, поэтому
  правки в `node_modules` всегда временные.
* Правка клиентская: **увидется только после перезапуска DSH** (закрыть приложение полностью, включая
  трей, и открыть заново). Перезапуск в этой сессии не выполнялся.
* Правильное долгосрочное решение — отправить `locale/ru.json` + `ru`-словарь автору `dshmarket`

## R4b: серверный слой (`lib\*.js`) — трёхчастный формат

Отдельная задача (task-8), полный отчёт: `ru-market-lib2-report.md`. Кратко:

Серверные сообщения dshmarket двуязычные (`'中文 / English'` и пары `{zh, en}`), а половину выбирает
клиент. Код языка вычислялся бинарно (`zh` | иначе `en`), поэтому локаль `ru` получала английскую
половину, а одноязычные китайские строки (без `' / '`) возвращались как есть — то есть по-китайски.

Введён единый формат **`'<中文> / <English> / <Русский>'`**; `client\client.js` научился отдавать
`zh` → часть 0, `en`/`ja` → часть 1, `ru` → часть 2 (регресс en/ja недопустим — потому и три части).
Правлены 16 файлов `lib\*.js` (129 сообщений; `restart.js`, `profile.js`, `updates.js` содержат только
комментарии), плюс механизм в `client.js`. `routes.js` и `pnpm-compat.js` не трогались (task-6).

* Перевод живёт в @node_modules@ и **слетит при переустановке/обновлении этих плагинов** (@dsh plugin add …@,
  @pnpm install@, обновление из маркета) — плагины поставят свои оригинальные файлы. После любого такого
  действия перевод нужно применить заново (или просто жить с иероглифами в этих двух подписях).
* Дополнительно @pnpm install@ вычищает каталоги, не объявленные в зависимостях профиля, поэтому любые
  правки внутри @node_modules@ всегда временные.
* Изменения клиентские: увидятся **только после перезапуска DSH** (полностью закрыть приложение, включая
  трей, и открыть заново).
