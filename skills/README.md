# Скиллы агента: архитектура и реестр

Здесь живёт **рабочая** система скиллов агента: рантайм, реестр и модули источников.
Регламентные скиллы без Python-модуля (`direct-keywords`, `newbuild-ru-glossary`) отдаются DSH
из этого же каталога, но живут отдельно от реестра источников — см. раздел «Регламентные скиллы».

## Из чего состоит система

```
skills/
  runtime/              служебный слой — общий для всех скиллов
    core.py             контракт, статусы, журнал, переменные окружения, декоратор @skill
    http.py             HTTP на стандартной библиотеке, таймаут <= 10 с, точка подмены _transport
    registry.py         чтение реестра, run_skill / run_skill_result
  registry/
    skills_registry.json  реестр: имя, модуль, назначение, ключи, лимиты, вердикт проверки
  real_estate/          скиллы источников данных о недвижимости
  run_skill.py          CLI: --list, <skill> "<запрос>", --all "<запрос>", --json
  tests/                unittest (в проекте pytest не используется)
  logs/skill-runs.jsonl журнал прогонов (каталог в .gitignore)
```

Контракт скилла:

```python
fetch(query: str, **kwargs) -> list[dict]
```

Правила, которые гарантирует рантайм:

* возвращается **всегда** `list[dict]`, наружу исключение не выходит;
* нет ключа окружения → статус `skipped_no_key`, **предупреждение в лог** и `[]`;
* сервис не развёрнут → статус `not_deployed` и пояснение, что сделать;
* сеть/HTTP/разбор ответа упали → статус `error`, предупреждение в лог и `[]`;
* таймаут одного запроса не больше **10 секунд** (`clamp_timeout`); исключение —
  только явные операторские режимы, которые передают свой предел (`ceiling`,
  максимум `MAX_LONG_TIMEOUT` = 600 с);
* каждый вызов журналируется: скилл, запрос, статус, время выполнения, число записей;
* **защита от ложного успеха**: запись, в которой нет ни содержательных полей
  (`id`, `title`, `price`, `area`, `year_built`, `address`, `url`), ни исходного объекта
  в `raw`, отбрасывается — статус будет `empty`, а не `ok` (`is_empty_record`).

Честность данных: отсутствующее значение — `None`, а не `0` и не `""`.

## Как вызвать скилл

```powershell
$py = "$env:USERPROFILE/.dsh/dsh-runtimes/dsh-primary-runtime/dependencies/python/python.exe"
cd marketing-agents

& $py -m skills.run_skill --list
& $py -m skills.run_skill mcp_market "каркасные дома в спб"
& $py -m skills.run_skill --all "квартира москва"
```

Из кода:

```python
from skills.runtime import run_skill, run_skill_result

records = run_skill("mcp_market", "каркасные дома в спб")      # всегда list[dict]
info    = run_skill_result("reefapi", "квартира москва")        # + статус, ошибка, время
```

## Доступные скиллы

| Скилл | Назначение | Требуемые ключи | Ограничения бесплатного тарифа | Состояние |
|---|---|---|---|---|
| `mcp_market` | MCP Market Russia: поиск компаний строительного рынка РФ | нет | полностью бесплатно, ключ не требуется | **проверен живым запросом**: HTTP 200, 10 компаний |
| `reefapi` | Живые данные Avito и Cian через единый REST API ReefAPI | `REEFAPI_KEY` | 1 000 кредитов при регистрации, без карты; один пул кредитов на все API | проверен живьём; **в недельный цикл НЕ входит** (поиск Авито 25–280+ с). Доступен режим разовой проверки `fetch_long()` + `01-competitor-watch/scripts/reefapi_deep_check.py` |
| `rentscout` | Агрегация объявлений об аренде с локального сервиса RentScout | нет (локальный сервис) | ключ не требуется, но нужно развернуть локально | **развёртывание не выполнено** — скилл объясняет, почему и что сделать |
| `mcp_rosreestr` | Росреестр/НСПД: кадастровая стоимость, площадь, год постройки, адрес | нет (локальный MCP-сервер) | open-source под MIT, ключ не требуется | нужен локальный сервер и **российский IP**; иначе `not_deployed` |
| `apify` | Запуск готовых акторов Apify для парсинга недвижимости | `APIFY_TOKEN`, `APIFY_ACTOR` | $5 кредитов ежемесячно | ключа нет → пустой список; актор Cian дублирует `cian-connector` |
| `rentcast` | Аренда и продажа, рынок США | `RENTCAST_KEY` | 50 запросов в месяц | сервис отвечает `401` без ключа; **только США** |
| `zillapi` | Данные Zillow (США) через REST API Zillapi | `ZILLAPI_KEY` | 100 кредитов без кредитной карты | `/pricing` подтверждает 100 кредитов; **только США** |
| `developer_pricing` | Цены «от» по позициям каталога с публичной страницы застройщика | нет | бесплатно, ключ не нужен | проверен на фикстуре (`01-competitor-watch/tests/fixtures/pages/site-price-cards.html`): «взнос» и «цена за м²» отброшены, ₽/м² вне коридора 120 000…1 200 000 не публикуется. Только анонимный HTTP: каркас SPA → `not_deployed` |
| `yandex_direct` | Яндекс.Директ API v5 (Агент 2): доступ, кампании `Campaigns.get`, асинхронные отчёты Reports; счётчик Метрики (`Authorization: OAuth`) | `YANDEX_OAUTH_TOKEN` (запасное имя — `YANDEX_DIRECT_TOKEN`) | бесплатно в рамках аккаунта | **живого токена нет**: проверено тестами на мок-транспорте (10.11.2026, 36 тестов). CLI панели: `python -m skills.direct_api --check --json` → без токена `skipped_no_key`, код 0. Только чтение: ставки и бюджеты не меняются; песочница Reports не поддерживает |

Подробные описания входов/выходов — в docstring каждого модуля в `real_estate/` и `direct_api/`.

## Регламентные скиллы (без Python-модуля)

Такие скиллы не ходят в сеть и не входят в `registry/skills_registry.json` (реестр — только
для модулей с контрактом `fetch`): они задают порядок работы агента и границы.

| Скилл | Назначение | Состояние |
|---|---|---|
| `direct-keywords` | Агент 2, Яндекс Директ: семантика → кластеры → кампании → объявления → выгрузка/API → оптимизация. Контракт доступов Директа v5 и Метрики. | **регламент интегрирован 10.11.2026**; API-автоматизации ещё нет, результат — черновики (`../02-keywords-direct/`) |
| `newbuild-ru-glossary` | Терминология новостроек: лоты, комнатность, отделка, классы, метрики цен, формулировки акций. | справочник, используется Агентами 1–2 |

### Роль Head of Performance (создана 11.11.2026)

Восемь регламентных скиллов уровня «руководитель performance-направления»; цель — выручка и окупаемость
(ROMI/ДРР), а не клики. Запись в аккаунт — только по явному подтверждению; токены — из `.env`.

**Все они относятся к Агенту 2** (`agent-2-direct-semantics`): список закреплён в `registry/agents.yaml`
(поле `skills`), карточка агента в панели показывает их и даёт запуск — «Проверить доступ к API Директа»
и «Отчёт Метрики за 30 дней».

| Скилл | Назначение | Состояние |
|---|---|---|
| `yandex-performance-head` | Роль-зонтик: цикл работ, формат ответа (резюме → детали → следующий шаг) | регламент |
| `performance-unit-economics` | AOV, маржа, CR, LTV → CAC/CPL/целевой ДРР; медиаплан и 3 сценария | регламент + формулы |
| `direct-campaign-management` | Директ API v5: кампании, группы, объявления, ключи, ставки, автостратегии | **только чтение**: заявка на API ждёт одобрения (ошибка 58) |
| `metrika-cross-analytics` | Цели, офлайн-конверсии из CRM, `stat/v1/data`, площадки РСЯ, корректировки | чтение работает; офлайн-конверсии не реализованы |
| `yandex-wordstat` | Семантика, спрос, динамика и гео, новые кластеры | **не подключено**: у Wordstat нет публичного API (перешёл в платный Yandex Search API) |
| `yandex-audience` | Сегменты из CRM/поведения, ретаргетинг РСЯ | **не подключено**: нужен сервис Яндекс.Аудиторий |
| `ppc-audit` | Чек-лист аудита, минусация, перераспределение бюджета | регламент |
| `performance-ops` | Циклы день/неделя/месяц, отчёт руководству (план-факт, ROMI, KPI) | регламент |

Разбор доступов и внешних решений — `../docs/research/yandex-performance-apis-2026-11-11.md`.

Если регламентный скилл обрастает автоматизацией, пишется модуль `fetch`-контракта, и только
затем он попадает в реестр и таблицу выше.

### Что эти скиллы не дают

Это важно для планирования и уже проверено фактически:

* `mcp_market` — каталог **строительных подрядчиков**, а не база лотов: цен квартир,
  площадей и корпусов там нет. Цена за м² приходит отдельными полями.
* `rentcast` и `zillapi` — **рынок США** (Zillow), к новостройкам Москвы неприменимы.
* `apify` (актор Cian), `reefapi` (Avito/Cian) и `rentscout` (Avito/Cian) функционально
  **пересекаются** с уже работающими путями проекта: `registry/sources.yaml` (cian, avito,
  yandex-realty, domclick) и коннекторами `cian-connector` / `avito-connector`.
* Канонического open-source проекта RentScout с набором источников
  «Avito, Cian, Domofond, Yandex Realty, DomClick» **не найдено**; RU-форк
  `CreatmanCEO/rentscout` помечен как Commercial и работает с другим набором площадок.

## Ключи и переменные окружения

* Шаблон: [`../.env.example`](../.env.example) — там перечислены все переменные.

## Тесты

```powershell
cd marketing-agents
& $py -m unittest discover -s skills/tests -t . -v
```

* `test_contract.py` — контракт рантайма: реестр, таймауты, поведение без ключа,
  отлов исключений, формат записи, журнал, `run_skill`;
* `test_real_estate_ru.py`, `test_real_estate_us.py` — модули источников на мок-транспорте;
* `test_developer_pricing.py` — выбор цены с сайта застройщика (дефект F10): слова-обманки,
  коридор ₽/м², честный `not_deployed` при блокировке анонимного HTTP;
* `test_adversarial.py` — состязательные проверки режимов отказа: ложный успех на
  мусорном ответе, отсутствие ключа не доходит до сети, таймаут нельзя превысить
  ни аргументом, ни переменной окружения, журнал пишется при любом исходе;
* `test_direct_api.py` — `yandex_direct` (Яндекс.Директ API v5) на мок-транспорте:
  нет токена → `skipped_no_key` и ни одного запроса, успешный `Campaigns.get`,
  `Client-Login` только при заданной переменной, песочница меняет хост, HTTP 500 → `error`,
  Reports 201/202 → `pending`, таймаут не поднять аргументом, контракт CLI `--check --json`.

Всего **144 теста**.

## Как добавить новый скилл

1. Создать модуль, взяв за образец `real_estate/mcp_market.py`.
2. Добавить запись в `registry/skills_registry.json` (`name`, `module`, `entry`,
   `purpose`, `required_env`, `free_tier`, `limits`, `verified`).
3. Добавить тесты в `tests/`.
4. Прогнать `python -m unittest discover -s skills/tests -t .`.
5. Согласовать с пользователем (правило сессии от 2026-11-04).
