# Skill 2: управление кампаниями в Яндекс.Директе (API v5)

## Статус (11.11.2026)

* **Доступ к API Директа ждёт одобрения заявки** — запись и чтение возвращают
  `ошибка 58: Незавершённая регистрация`; OAuth-токен валиден, авторизация проходит.
* **Работает только чтение** (`Campaigns.get`, `Reports`); создание и правка объектов сейчас
  невозможны, результат — подготовленный план вызовов API, который выполнится после одобрения.
* Wordstat и Аудитории не подключены; офлайн-конверсии не реализованы.
* Проверка: `python -m skills.direct_api --check --json` (без токена — `skipped_no_key`, код 0).

## Что закрывает

| Сервис API v5 | Методы | Назначение |
|---|---|---|
| `Campaigns` | `get`, `add`, `update`, `suspend`, `resume`, `archive` | кампании: ЕПК, текстовые, смарт-баннеры |
| `AdGroups` | `get`, `add`, `update` | группы, привязка региона и стратегии |
| `Ads` | `get`, `add`, `update` | объявления, быстрые ссылки, уточнения |
| `Keywords` | `get`, `add`, `update` | ключевые фразы и минус-слова |
| `Bids` | `set`, `setAuto` | ручные ставки и автостратегии (`set_strategy`) |
| `BidModifiers` | `get`, `add` | корректировки (передаёт `metrika-cross-analytics`) |
| `Reports` | отдельный протокол, TSV | статистика для решений |

Эндпоинт: `POST https://api.direct.yandex.com/json/v5/{service}`,
тело `{"method": "...", "params": {...}}`. Песочница — `api-sandbox.direct.yandex.com`.

## Подготовительный чек-лист перед вызовом API

1. Есть явное подтверждение пользователя на конкретное изменение (что, где, сколько).
2. Проверены доступы: `--check --json`; ошибка 58 — запись не выполняем, план откладываем.
3. Оценена стоимость вызова и остаток `Units`; при остатке < 10 % — предупреждение.
4. Сверены лимиты и обязательные поля по официальной документации Директа (перед вызовом).
5. Зафиксированы объекты и их `Id`; правки — точечные, без «заодно перепишем всё».
6. Бюджет и стратегия указаны цифрами, не «примерно».
7. Заведён журнал: время, объект, было → стало, кто подтвердил.
8. Новые кампании — в статусе «черновик/пауза», никогда не «включено» с первого шага.

## Порядок работы

1. Черновик структуры из `direct-keywords` (кластеры → кампании → группы → объявления).
2. Валидация лимитов: длины заголовков/текстов, число фраз в группе, список минус-слов.
3. **План изменений таблицей** пользователю: объект, действие, ключевые параметры, оценка стоимости.
4. Подтверждение → вызов API (пакетно, по одному сервису).
5. Проверка ответа: `error` / `warnings`, что создалось, что отклонено модерацией.
6. Отчёт о различиях «план / факт» и запись в журнал действий.

## Автостратегии

* **Не переключать автостратегию чаще, чем раз в 2–4 недели** — стратегии учатся, частые
  переключения обнуляют обучение и статистику.
* Смена цели, бюджета или стратегии — отдельная гипотеза с датой старта и датой оценки.
* Принудительно не «докручивать» ставки внутри обучения (`Bids.set` поверх `setAuto`).

## Границы и безопасность

* **Запись — только по явному подтверждению пользователя**: создание, изменение, удаление
  кампаний, групп, объявлений, ключей, ставок и бюджетов. Молчаливое согласие не считается.
* Токены — только из `marketing-agents/.env` (`YANDEX_OAUTH_TOKEN`, `YANDEX_DIRECT_CLIENT_LOGIN`,
  `YANDEX_METRICA_COUNTER_ID`); в текстах — `Bearer [СКРЫТО]`, значение не выводить.
* Честность: нет данных — «данных нет»; у каждой цифры источник и дата.
* Цели Метрики без согласования не менять.
* Маркировка рекламы (ERID) и требования к рекламе застройщиков — до выгрузки.
