## Что проверяет (поведение, а не разметка)

| Шаг | Что доказывает |
|---|---|
| sidebar.items | каждый пункт меню меняет адрес и содержимое |
| analytics.modes | три режима Аналитики дают разные отпечатки ВИДИМОГО содержимого |
| agents.tabs | вкладки «Агентов» меняют содержимое (заглушки «· скоро» пропускаются) |
| accordion | раскрытие аккордеона меняет содержимое |
| search.view / search.empty | поиск сужает строки; пустой результат объяснён словами |
| filters | каждый фильтр меняет количество строк |
| sort | после клика таблица ЗАНОВО запрашивается из DOM: существует, число строк, порядок |
| menu.create / menu.user / menu.palette | меню открываются и закрываются Esc |
| drawer | модал открывается, закрывается Esc и кликом вне, скролл не залипает |
| hash.routing | #раздел, #agents/подвкладка, назад/вперёд |
| empty.states | пустые таблицы объясняют причину, а не показывают ноль |
| dead.buttons | у кнопок есть наблюдаемый эффект (изменение body / адреса / модала) |
| actions.collect / actions.report | действие с подтверждением: 1-й клик — видимая плашка в #view, 2-й — результат |
| actions.staleConfirm | после выполнения плашка подтверждения убирается |
| dialogs.native | нативных confirm/alert нет (они блокируют интерфейс) |
| js.errors | нет ошибок JS за время обхода |

## Ключевое различие отпечатков

- fpВИДИМ — по #view.innerText: скрытое через display:none / hidden НЕ попадает. Вердикт по переключателям — по нему.
- fpВЕСЬ — по textContent, включая скрытое (для контраста).
  Именно сравнение только скрытого текста давало ложный «успех» приёмки (дефект T73).
