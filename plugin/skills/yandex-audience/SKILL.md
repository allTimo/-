# Skill 4b: сегменты и ретаргетинг (Яндекс.Аудитории)

## Статус (11.11.2026)

* **Яндекс.Аудитории не подключены.** Сегменты через API не создаются и не передаются в Директ:
  нет подтверждённого доступа к сервису Аудиторий.
* Что нужно для подключения: доступ к Яндекс.Аудиториям тем же OAuth-приложением проекта
  (Client ID сохранён в `docs/agent2-integration-2026-11-10.md`), право загрузки сегментов
  и привязка сегмента к кампании РСЯ.
* Пока сегменты собираются **вручную** (интерфейс Аудиторий Метрики/Директа) и используются
  как черновик для `direct-campaign-management`.
* Смежное: **API Директа ждёт одобрения заявки (ошибка 58)** — доступно только чтение
  (`Campaigns.get`, `Reports`); Метрика работает (счётчик, цели, `stat/v1/data`);
  Wordstat не подключён; офлайн-конверсии из CRM не реализованы.

## Какой доступ нужен

| Доступ | Назначение | Состояние |
|---|---|---|
| Яндекс.Аудитории (API/OAuth проекта) | создание и обновление сегментов | нет |
| Метрика: цель и `ym:s:clientID` | сегмент «достигшие/не достигшие цели» | частично (цели читаются) |
| Выгрузка базы CRM с согласием на рекламу | сегмент по клиентам, look-alike | нет |
| Загрузка сегмента в кампанию РСЯ | применение в Директе | нет |

## Порядок работы

1. **Согласование и правовое основание.** Загрузка базы CRM — только с подтверждением
   пользователя и наличием согласия на рекламную обработку; без основания не начинаем.
2. **Сегменты по поведению на сайте** (Метрика): посетители целевых страниц, достигшие микроцели
   (квиз, калькулятор), не достигшие макроцели, брошенная форма.
3. **Сегменты из CRM** (план): клиенты по статусам сделок, отказники, «дорогие» сегменты для
   исключения. Пока не реализовано — помечать честно.
4. **Ретаргетинг в РСЯ:** отдельная кампания, свои тексты и офферы под каждый сегмент,
   отдельные цели Метрики для измерения.
5. **Исключения:** не показывать тем, кто уже купил; исключать нецелевые сегменты и площадки.
6. **Оценка:** сегмент считается рабочим только при статистике — расход, лиды, CR, CPL
   (`metrika-cross-analytics`); иначе «данных нет».
7. **Передача в Директ:** создание кампании и условий показа — только по явному подтверждению.

## Правила

* Сегмент без источника, размера и даты сборки не используется.
* Персональные данные не выводим в отчёты и чат: только агрегаты (размер сегмента, CR).
* Молчаливое согласие подтверждением не считается — ни на загрузку базы, ни на создание кампании.
* Токены — только из `marketing-agents/.env` (`YANDEX_OAUTH_TOKEN`, `YANDEX_DIRECT_CLIENT_LOGIN`,
  `YANDEX_METRICA_COUNTER_ID`); в текстах — `Bearer [СКРЫТО]`.
* Честность: нет данных — «данных нет»; у каждой цифры источник и дата.
* Контроль баллов API (`Units`): остаток < 10 % — предупреждение.
* Не менять существующие цели Метрики без согласования.
