# Skill 5: аудит и поиск точек роста

## Статус (11.11.2026)

**ОБЯЗАТЕЛЬНО ПЕРЕД ПРИМЕНЕНИЕМ:** прочитать скилл `ppc-checklist` — 105 пунктов аудита и правило
«сначала проверка, потом рекомендация». В ответе указывать, что проверено, а что нет.

* **API Директа ждёт одобрения заявки (ошибка 58)** — аудит читает то, что доступно:
  `Campaigns.get` и `Reports`; часть данных (настройки групп, ставки) недоступна, это отмечаем в отчёте.
* **Метрика работает**: счётчик, цели, `stat/v1/data` — конверсии по фразам и посадочным.
* **Wordstat не подключён** — частотность и оценка семантики вручную, поле «данных нет».
* **Аудитории не подключены**; **офлайн-конверсии из CRM не реализованы** — продажи в отчёте
  могут отсутствовать, тогда пишем «данных нет», а не ноль.
* Проверка: `python -m skills.direct_api --check --json`, `--metrika-report --from/--to`.

## Чек-лист аудита

| Блок | Что проверяем | Источник |
|---|---|---|
| Структура | поиск и РСЯ разделены, один интент на группу, посадочная под кластер | `Campaigns.get`, черновики `direct-keywords` |
| Стратегии | тип стратегии под цель (продажи, а не клики), срок обучения 2–4 недели | настройки кампаний |
| Минус-слова | общий список + мусорные интенты (аренда, работа, вторичка, отзывы) | `Keywords`, `Reports` по запросам |
| Объявления | заголовки и тексты в лимитах, УТП, быстрые ссылки, уточнения, релевантность группе | `Ads` |
| Аналитика | цели Метрики размечены, макро/микро разделены, отчёты по фразам и посадочным | `stat/v1/data` |
| Экономика | CAC/CPL против целевых, ДРР, ROMI, план/факт бюджета | `performance-unit-economics` |
| Гео и корректировки | регионы показа, корректировки по полу/возрасту/гео при достаточной статистике | Метрика + настройки |

## Поиск скрытых резервов

1. **Отчёт по поисковым запросам** (`Reports` Директа + `ym:s:searchPhrase`): собрать запросы
   с расходом, но нулевой конверсией за период → кандидаты в минус-слова.
2. **Минусация** — список фраз с расходом, кликами, лидами, вывод «минусовать»/«оставить»;
   общий список минус-слов — отдельным артефактом.
3. **Площадки РСЯ** — отключение площадок с расходом выше порога и нулевой конверсией
   (`metrika-cross-analytics`).
4. **Перераспределение бюджета** — с кампаний с ДРР выше допустимого на маржинальные:
   таблица «откуда → куда → сколько → ожидаемый эффект», суммы обоснованы цифрами.
5. **Поиск незакрытого спроса** — кластеры из `direct-keywords` без кампаний (нужна частотность
   из Wordstat — сейчас вручную).
6. **Стоп-правила** — бюджет без заявок N дней → пауза и разбор, без «ещё немного докрутим».

## Формат вывода аудита

1. **Резюме для руководителя**: 1–2 предложения о бизнес-эффекте (сколько денег и куда).
2. **Таблица находок**: приоритет | проблема | доказательство (метрика, период, источник) | действие.
3. **План изменений через API**: объект, действие, параметры — только после подтверждения.
4. **Что не удалось проверить**: недоступные блоки (ошибка 58, Wordstat, Аудитории, CRM) и что
   нужно, чтобы их закрыть.
5. **Следующий шаг**: что подтвердить или какие данные запросить.

## Правила

* **Запись — только по явному подтверждению пользователя**: минусация, отключение площадок,
  смена ставок, бюджетов и стратегий. Молчаливое согласие подтверждением не считается.
* У каждой цифры — источник (Директ `Reports`, Метрика `stat/v1/data`, пользователь) и дата.
* Нет данных — «данных нет»; недостающие блоки аудита не домысливаем.
* Существующие цели Метрики без согласования не менять.
* Контроль баллов API (`Units`): остаток < 10 % — предупреждение.
* Токены — только из `marketing-agents/.env`; в текстах — `Bearer [СКРЫТО]`.
