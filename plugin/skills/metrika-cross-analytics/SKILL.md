# Skill 3: сквозная аналитика (Метрика)

## Статус (11.11.2026)

* **Метрика работает**: счётчик доступен (id в `YANDEX_METRICA_COUNTER_ID`), заголовок
  `Authorization: OAuth [СКРЫТО]` (не Bearer), цели и `stat/v1/data` читаются.
* **API Директа ждёт одобрения заявки** — ошибка 58; из Директа доступно только чтение
  (`Campaigns.get`, `Reports`), поэтому связка «расход ↔ конверсия» собирается по отчётам.
* **Офлайн-конверсии из CRM не реализованы** — выгрузка статусов сделок в Метрику не настроена.
* Wordstat и Аудитории не подключены.
* CLI: `python -m skills.direct_api --metrika-counters`, `--metrika-report --from/--to`.

## Порядок работы

1. **Счётчик и цели.** Проверить список целей через `management/v1/counter/{id}/goals`.
   Разметить: макроцели (заявка, звонок, сделка) и микроцели (квиз, калькулятор, карта).
2. **Не менять существующие цели без согласования** — правка ломает историю; новые цели
   создавать отдельными сущностями, старое не переименовывать.
3. **Отчёты** через Reporting API `https://api-metrika.yandex.net/stat/v1/data`:
   разрезы — источник/канал, кампания, фраза (`ym:s:searchPhrase`), посадочная (`ym:s:startURL`).
4. **Офлайн-конверсии** (план, не реализовано): статусы сделок из CRM связать с
   `ym:s:clientID` / телефоном и загрузить; пока считаем только онлайн-конверсии — честно указывать.
5. **Оптимизация по данным:** отключить площадки РСЯ с нулевой конверсией и расходом выше порога;
   корректировки по полу, возрасту, гео — только после накопленной статистики.
6. **Вывод — в Директ**: корректировки и отключения передаются как план в
   `direct-campaign-management` и выполняются только после подтверждения.

## Метрики Метрики (что берём)

| Метрика | Смысл | Использование |
|---|---|---|
| `ym:s:visits` | визиты | знаменатель для CR |
| `ym:s:users` | посетители | охват, частота |
| `ym:s:bounceRate` | отказы | качество трафика |
| `ym:s:pageDepth` | глубина просмотра | вовлечённость |
| `ym:s:avgVisitDurationSeconds` | время на сайте | качество трафика |
| `ym:s:goal<id>reaches` | достижения цели | лиды, микроцели |
| `ym:s:goal<id>conversionRate` | конверсия в цель | CR_lead |
| `ym:s:goal<id>revenue` | выручка цели (если передаётся) | ДРР, ROMI |
| `ym:s:searchPhrase` | поисковая фраза | минусация в `ppc-audit` |
| `ym:s:startURL` | посадочная | какие страницы продают |
| `ym:s:clientID` | идентификатор клиента | ключ для офлайн-конверсий |

## Правила

* У каждой цифры — источник (`stat/v1/data`), разрез, период и дата выгрузки.
* Нет данных по цели или периоду — пишем «данных нет», а не ноль.
* Расхождения Метрика ↔ Директ объяснять (атрибуция, окно, часовой пояс), не усреднять молча.
* РСЯ-площадки отключаем порогом: расход ≥ заданного минимума и конверсий 0 за период.
* Корректировки — по группам с достаточной статистикой; иначе «данных нет».
* Контроль баллов API (`Units`) при массовых запросах; остаток < 10 % — предупреждение.

## Границы и безопасность

* Запись в Директ (отключение площадок, корректировки, цели) — **только по явному
  подтверждению** пользователя; молчаливое согласие не считается.
* Токены — только из `marketing-agents/.env` (`YANDEX_OAUTH_TOKEN`,
  `YANDEX_METRICA_COUNTER_ID`, `YANDEX_DIRECT_CLIENT_LOGIN`); в текстах — `Bearer [СКРЫТО]`.
* Существующие цели Метрики без согласования не менять.
