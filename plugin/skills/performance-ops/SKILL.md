# Skill 6: процессы, циклы и отчётность

## Статус (11.11.2026)

* **API Директа ждёт одобрения заявки (ошибка 58)** — мониторинг опирается на чтение:
  `Campaigns.get`, `Reports`; запись (правки, ставки, бюджеты) недоступна и в любом случае
  требует подтверждения пользователя.
* **Метрика работает**: счётчик, цели, `stat/v1/data` — источник конверсий и лидов.
* **Wordstat и Яндекс.Аудитории не подключены** — семантика и сегменты вручную.
* **Офлайн-конверсии из CRM не реализованы** — продажи в отчётах часто «данных нет»;
  не подменяем их нулём.
* CLI: `python -m skills.direct_api --check --json`, `--metrika-report --from/--to`,
  `--metrika-counters`.

## Три цикла

| Цикл | Что делаем | Выход |
|---|---|---|
| Ежедневно | аномалии: скачок расхода/CPC, падение лидов, нулевые показы, рост отказов, расход без заявок | короткая сводка: факт, отклонение, причина, действие |
| Еженедельно | гипотезы: тесты объявлений, минусация, корректировки, перераспределение бюджета | таблица гипотез со статусом и результатом |
| Ежемесячно | отчёт руководству: план/факт бюджета, лиды, продажи, ROMI, ДРР, KPI | отчёт + решения на следующий месяц |

## Ежедневный мониторинг аномалий

1. Снять факт за сутки: расход, клики, CPC, лиды, CR (Метрика), ДРР.
2. Сравнить с базой: среднее за 7 дней и за 28 дней; отклонение > порога → аномалия.
3. Правило N дней без заявок при расходе → предложить паузу и разбор (стоп-правило).
4. Ничего не менять молча: сначала причина, затем предложение, затем подтверждение.

## Еженедельные гипотезы

Формат записи гипотезы: дата старта | что меняем | ожидаемый эффект | метрика успеха |
дата оценки | статус (ждёт / идёт / принята / отклонена).

* Автостратегии не трогать чаще, чем раз в 2–4 недели (`direct-campaign-management`).
* Одна гипотеза — одно изменение; иначе результат не атрибутируется.
* Оценка — по деньгам (CPL, CAC, ДРР), а не по CTR.

## Ежемесячный отчёт руководству

| Блок | Содержание |
|---|---|
| План/факт бюджета | план, факт, отклонение в ₽ и %, причина |
| Лиды | количество, CPL, динамика к прошлому месяцу |
| Продажи и выручка | из CRM/Метрики; нет данных — «данных нет» |
| ROMI и ДРР | факт против целевого (`performance-unit-economics`) |
| KPI | какие выполнены, какие нет, почему (объективно) |
| Решения | что делаем дальше: масштабировать, чинить, остановить |
| Риски и блокеры | ошибка 58, Wordstat/Аудитории, офлайн-конверсии, остаток `Units` |

Формат ответа (как у роли): **резюме руководителю → детали таблицами → следующий шаг**.
У каждой цифры — источник и дата отчёта.

## Правила

* **Запись в Директ — только по явному подтверждению пользователя**; молчаливое согласие
  подтверждением не считается. План без подтверждения не выполняем.
* Токены — только из `marketing-agents/.env` (`YANDEX_OAUTH_TOKEN`, `YANDEX_METRICA_COUNTER_ID`,
  `YANDEX_DIRECT_CLIENT_LOGIN`); в текстах — `Bearer [СКРЫТО]`, значение не выводить.
* Честность: нет данных — «данных нет»; у каждой цифры источник и дата.
* Существующие цели Метрики без согласования не менять — ломает историю.
* Контроль баллов API (`Units`): остаток < 10 % — предупреждение.
* Журнал действий обязателен: что меняли, когда, зачем, кто подтвердил.
