# Агент 2: контекстная реклама в Яндекс Директе

Загружай этот скил, когда пользователь просит «собрать семантику», «сделать кампании в Директе»,
«сгруппировать ключи», «написать объявления», «выгрузить в Директ», «посмотреть статистику кампаний»,
«настроить цели в Метрике».

## Статус (обновлён 10.11.2026)

* Регламент полного цикла зафиксирован здесь и в `docs/agent2-yandex-direct-plan.md`.
* **API-автоматизация ещё не подключена**: Python-модуля, который ходит в Директ и Метрику, пока нет,
  токены в окружении не заданы. Результат работы — **черновики для человека** (семантика, структура,
  тексты, XLS под Директ Коммандер), а не живые изменения в аккаунте.
* Раздел «Доступы и API» ниже — контракт для следующего этапа: по нему пишется модуль
  `skills/direct_api/` (stdlib Python, ключи из `.env`), после чего кнопка запуска Агента 2
  в панели может быть включена.

## Что делает Агент 2

1. **Сбор семантики**: Wordstat и подсказки Яндекса; запросы по ЖК, районам, метро; параметры лота
   (студия, 1–3 комнаты, отделка, ипотека, рассрочка, цена «от»); бренды своих ЖК и конкурентов; гео-модификаторы.
2. **Чистка**: минус-слова по мусорным интентам — аренда, снять, работа, вакансии, вторичка, б/у,
   отзывы, фото, ЖКХ, аварийный, снос, форум, ремонт, обои.
3. **Лемматизация и дедупликация**: «квартира» / «квартиры» / «квартиру» — один кластер.
4. **Кластеризация по интенту**: (а) бренд нашего ЖК, (б) бренд конкурента, (в) район/метро,
   (г) параметры лота, (д) цена/ипотека/рассрочка, (е) общие запросы по новостройкам Москвы.
5. **Сборка кампаний**: поиск и РСЯ отдельно; группы по кластерам, один смысловой интент на группу;
   посадочная страница под каждый кластер обязательна.
6. **Объявления**: заголовок 1 и 2, текст, быстрые ссылки, уточнения — в лимитах Директа;
   для премиума сдержанный тон, без «дёшево» и «успей».
7. **Выгрузка и контроль**: XLS под Директ Коммандер и/или API v5; после загрузки — проверка,
   что создалось, что отклонено модерацией, и отчёт о различиях.
8. **Оптимизация**: статистика из аккаунта, чистка неэффективных ключей и площадок, A/B объявлений,
   отчёт клиенту и правило остановки (бюджет без заявок N дней → пауза и разбор).

## Контракт ТЗ от пользователя

Агент 2 запускается только по ТЗ. Минимальный состав: ЖК/проект, класс, локация, УТП,
цена входа и диапазон, срок сдачи, ссылка на посадочную, целевой регион, бюджет в месяц,
ограничения по брендам и конкурентам, желаемые группы.

Нет ТЗ — сначала собираем ТЗ (форма — `02-keywords-direct/inbox/`), а не придумываем вводные.

## Доступы и API (контракт следующего этапа)

Только официальные API, ключи — из переменных окружения (`.env`, см. `../.env.example`):

| Переменная | Назначение |
|---|---|
| `YANDEX_DIRECT_TOKEN` | OAuth-токен Директа, заголовок `Authorization: Bearer ...` |
| `YANDEX_DIRECT_CLIENT_LOGIN` | Логин клиента для агентских аккаунтов, заголовок `Client-Login` (пусто для своего) |
| `YANDEX_DIRECT_SANDBOX` | `1` — работать с песочницей `api-sandbox.direct.yandex.com` |
| `YANDEX_METRIKA_TOKEN` | OAuth-токен Метрики |
| `YANDEX_METRIKA_COUNTER_ID` | Номер счётчика клиента |

**Яндекс.Директ API v5**

* JSON API: `https://api.direct.yandex.com/json/v5/{service}`, песочница — `https://api-sandbox.direct.yandex.com/json/v5/{service}`.
* Отчёты: `https://api.direct.yandex.com/json/v5/reports` (отдельный протокол: заголовок `processingMode`, ответ TSV).
* Запрос, кроме Reports: `{"method": "...", "params": {...}}`, сервисы — `Campaigns`, `AdGroups`, `Ads`,
  `Keywords`, `Bids`, `BidModifiers`, `Dictionaries`. Методы — `get`, `add`, `update`, `delete`,
  `suspend`, `resume`, `archive`, `setAuto` (по сервису).
* Лимиты и формат ошибок сверять по официальной документации перед реализацией:
  <https://yandex.ru/dev/direct/doc/dg/concepts/about.html>.

**Яндекс.Метрика API**

* Базовый URL `https://api-metrika.yandex.net/management/v1`, авторизация тем же OAuth-токеном.
* Для Агента 2 нужны: цели и конверсии, отчёты по источникам/кампаниям, счётчики клиента.
* Документация: <https://yandex.ru/dev/metrika/doc/api2/concept/about.html>.

## Порядок работы

1. ТЗ и доступы (этап 1 плана) — без них не стартовать.
2. Семантика и кластеры → `02-keywords-direct/keywords/`, `clusters/`.
3. Структура кампаний и групп → `campaigns/`.
4. Объявления → `ads/`; проверка на лимиты и модерацию.
5. Черновик выгрузки → `exports/` (XLS Коммандер) и/или запрос к API в режиме `sandbox`.
6. Загрузка в аккаунт — только в статусе «черновик/пауза», никогда не «включено».
7. Отчёты и оптимизация — по данным аккаунта, а не «на глаз».

## Границы и безопасность

* **Черновик для человека.** Ключи, объявления и структура — предложение, а не приказ аккаунту.
* **Ставки, бюджеты, включение кампаний — только по явному подтверждению** в текущем диалоге.
  Молчаливое «само собой понятно» подтверждением не считается.
* **Секреты — вне репозитория**: только `.env` / переменные окружения, в текстах — имена переменных.
* **Честность данных**: нет данных — пишем «данных нет», а не ноль; у каждой цифры — источник и дата.
* **Маркировка рекламы (ERID)** и требования к рекламе застройщиков (проектная декларация,
  «не является офертой») проверяются до выгрузки.
* **Предохранитель**: бюджет без заявок N дней → пауза и разбор, без «ещё немного докрутим».
* **Журнал действий** с чужими аккаунтами обязателен: что меняли, когда, зачем.
