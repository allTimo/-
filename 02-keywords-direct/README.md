модуль API — `skills/direct_api/`, итог — `docs/agent2-integration-2026-11-10.md`.

## Что здесь лежит

```
02-keywords-direct/
├── inbox/        ТЗ и исходные списки от вас
├── keywords/     сырая семантика и чистка
├── clusters/     кластеры с интентами
├── campaigns/    структура кампаний и групп
├── ads/          заголовки и тексты объявлений
├── exports/      файлы под Директ Коммандер и запросы API
```

## Что уже сделано

- Регламент полного цикла (семантика → кластеры → кампании → объявления → выгрузка → оптимизация)
  в скиле `direct-keywords`; DSH отдаёт его как скилл проекта.
- Модуль `skills/direct_api`: проверка доступа, список кампаний (`Campaigns.get`), отчёты (`Reports`,
  асинхронно: «готовится» = `pending`). Только чтение, ставки и бюджеты не меняет.
- Карточка Агента 2 в панели включена: кнопка «Проверить доступ к API Директа» пишет прогон в журнал
  и честно сообщает, если токена нет.
- Форма ТЗ (`inbox/TZ-template.md`), заполненное ТЗ по ЖК «Свет» и пробный кластер: 68 фраз,
  10 кластеров, структура поиск + РСЯ, 20 объявлений.

## Чего ещё нет

- `YANDEX_OAUTH_TOKEN` в `marketing-agents/.env` — без него живой аккаунт не читается
  (устаревшее имя `YANDEX_DIRECT_TOKEN` поддерживается как запасной вариант; для Метрики —
  `YANDEX_METRICA_COUNTER_ID`, заголовок `Authorization: OAuth`).
  (текущий статус проверки: `skipped_no_key`, это не сбой).
- Частотности по Wordstat: в `keywords/*.csv` честно стоит «нет данных».
- Ответов клиента по ТЗ: цена входа и диапазон, бюджет, ограничения по брендам, посадочные,
  счётчик Метрики и цели, ERID и проектная декларация.
- XLS под Директ Коммандер и выгрузки в аккаунт (`exports/` пока пуст).

## Как запускать

1. Открыть панель → «Агенты» → карточка «Агент 2 — Семантика и кампании Яндекс Директа» →
   блок «Кабинеты Яндекс.Директа».
2. Нажать «Подключить кабинет»: откроется новая вкладка Яндекса. Войти в аккаунт с доступом к нужному
   кабинету Директа, разрешить доступ — на странице будет показан OAuth-токен.
3. Скопировать токен, вставить в поле «Токен» (для агентского аккаунта заполнить «Логин клиента»,
   для тестов поставить галочку «Песочница») и нажать «Проверить и сохранить». Токен проверяется живым запросом `Campaigns.get`; успешный кабинет появится
   в списке, неудачный — нет (ошибка Директа показывается как есть).
4. Проверить доступ вручную: `python -m skills.direct_api --check` (из `marketing-agents/`) —
   или кнопкой «Проверить» у кабинета в списке.

Client ID приложения уже сохранён (10.11.2026). Client secret для этого потока не нужен и в файлы не пишется.

## Границы

Изменение ставок, бюджетов и включение кампаний — только по явному подтверждению пользователя.
Результат по умолчанию — черновик для человека; выгрузка в аккаунт идёт в паузе/черновике.
