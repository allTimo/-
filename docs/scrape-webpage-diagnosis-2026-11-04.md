# Диагностика `dsh-scrape-webpage`: «shell.run is not a function»

Дата: 04.11.2026. Задача: пункт 3 плана (починить/заменить сломанный `scrape_webpage`).
Исполнитель: Lead (первый исполнитель задачи упал, не оставив отчёта).

## Симптом

Инструмент `scrape_webpage` падает на любом URL:

```
Не удалось загрузить страницу: Не удалось выполнить команду: shell.run is not a function
Целевой URL: https://www.mr-group.ru/projects/zhk-seliger-siti
```

## Что удалось установить

1. Плагин установлен в профиле `desktop`:
   `C:\Users\Артем\.dsh\profiles\desktop\node_modules\dsh-scrape-webpage`, версия **1.0.0**.
2. Текст ошибки — из самого плагина, `lib/fetch.js:34-37`:

   ```js
   result = await shell.run(shell.resolve(request))
   } catch (err) {
     throw new Error('Не удалось выполнить команду: ' + String((err && err.message) || err))
   ```

3. Сервис берётся так — `lib/index.js:97` и `:137`: `const shell = ctx.get('shell')`.
   Рядом стоит проверка только на отсутствие сервиса целиком (`lib/index.js:98-99`):
   «В этом окружении нет ни доступного web-провайдера … ни службы shell».
   Проверки «есть ли у службы метод `run`» нет — поэтому вместо понятного сообщения
   наружу уходит `TypeError: shell.run is not a function`.
4. Значит на хосте **DeepSeek Harness 0.2.1-rc.5** служба `shell` в контексте есть, но её
   форма не совпадает с ожиданием плагина (`run` + `resolve`). Проверить определение службы
   в хосте не удалось: чекаут лежит внутри `app.asar` (`…\resources\app.asar`), распакованной
   копии на диске нет (`resources\app.asar.unpacked` — частичная), читать asar из сессии нечем.
   Это ограничение доказательной базы, а не вывод.
5. README плагина (кит.) подтверждает устройство: без host-провайдера `web` он падает на
   `shell` + `curl.exe`, а `shell` объявлен **необязательной** службой с «аккуратной ошибкой»
   при отсутствии — то есть падение по форме службы автор не предусмотрел.
6. Обновления нет: в кэше маркета (`.dsh-market/discovery-compatibility-v1.json`) у
   `dsh-scrape-webpage` только версия 1.0.0 — та же, что установлена. В `package.json`
   плагина **не объявлен** `engines.dsh` (в каталоге `enginesDsh: null`), поэтому фильтр
   совместимости маркета не мог предупредить о несовместимости с хостом.
7. Дополнительный факт: в `lib/` лежат файлы `*.bak-ru-20261031172430-*` — плагин ранее
   правился под русский язык другой сессией. Текущие файлы и бэкапы в районе строки 34
   совпадают, то есть локализация причиной не является.
