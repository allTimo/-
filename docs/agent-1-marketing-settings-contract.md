# Контракт маркетинговых настроек Агента 1 (v1, зафиксирован Lead 04.11.2026)

Настройки, которые клиент/оператор реально правит в карточке Агента 1, должны быть
**маркетинговыми** (кого и что смотрим) и **обязаны читаться движком**. Настройка,
которая ничего не меняет в работе агента, — дефект (см. D5 в `docs/backlog-2026-11-03.md`).

Файл настроек: `registry/agent-settings/agent-1-competitor-watch.yaml`
Схема панели: `dashboard/serve.mjs` → `AGENT_SETTINGS_SCHEMA`
Нормализация для панели: `dashboard/collector/lib/agent-settings.mjs`

## Группа 1. «Охват и радиус» — `agent1.watch` (существует, дополняется)

| поле | тип | диапазон/значения | смысл |
|---|---|---|---|
| `name` | str | — | название своего ЖК |
| `address` | str | — | адрес (по нему определяется локация) |
| `url` | str | — | сайт своего ЖК |
| `lat` / `lon` | str | — | координаты; пусто → определяются по адресу |
| `radius_km` | num | 1–100, дефолт 10 | радиус поиска конкурентов, км |
| `klass` | list | комфорт/бизнес/премиум/элит | сегмент подбираемых конкурентов |
| `max_candidates` | int | 1–200, дефолт 20 | **сколько конкурентов** попадает в работу/отчёт |
| `sources` | list | cian, avito, yandex-realty, domclick, web-search | где искать конкурентов |
| `price_min_per_m2` | int | ≥0 | нижняя граница сегмента, ₽/м² |
| `price_max_per_m2` | int | ≥0 | верхняя граница сегмента, ₽/м² |

## Группа 2. «Что анализировать» — `agent1.selection` (НОВАЯ)

| поле | тип | значения/диапазон | смысл |
|---|---|---|---|
| `room_types` | list | `0`(студия), `1`, `2`, `3`, `4`, `5+` | какие типы квартир учитывать |
| `area_min_m2` | num | 0–400, дефолт 0 | минимальная площадь лота |
| `area_max_m2` | num | 0–400, дефолт 0 = без ограничения | максимальная площадь лота |
| `price_min_rub` | int | ≥0, дефолт 0 | минимальная цена лота |
| `price_max_rub` | int | ≥0, дефолт 0 = без ограничения | максимальная цена лота |
| `exclude_first_floor` | bool | дефолт false | не учитывать первые этажи |
| `exclude_last_floor` | bool | дефолт false | не учитывать последние этажи |
| `finishes` | list | без отделки, white box, чистовая, с мебелью, unknown | какие типы отделки учитывать |

| `promo_only` | bool | дефолт false | оставить только лоты с акцией |
| `price_metric` | enum | `median` \| `mean` \| `min_max`, дефолт median | какой показатель цены печатать |
| `outlier_guard` | bool | дефолт true | отбраковывать аномалии и помечать срез недостоверным |
| `outlier_same_price_min_lots` | int | 2–50, дефолт 5 | с какого числа лотов одинаковая цена — артефакт |
| `outlier_ppm2_min` | int | дефолт 150000 | нижняя граница правдоподобного ₽/м² |
| `outlier_ppm2_max` | int | дефолт 800000 | верхняя граница правдоподобного ₽/м² |

## Обновление v2 (04.11.2026) — контракт переработки карточки

Полный контракт переработки: `docs/agent-1-rework-2026-11-04.md`. Изменения к v1:

1. **Дублей быть не должно.** В карточке Агента 1 ровно один блок «Тонкие настройки» и ни одного
   повторяющегося заголовка группы (было два одинаковых блока: обёртку навешивали и `app-views12.js`,
   и `app-views13.js`).
2. **`name`/`url` из карточки убраны.** Остаётся одно поле `agent1.watch.query` («Мой ЖК: название или
   сайт»); движок выводит `name`/`url` из него, если они пусты. Поля в YAML сохраняются.
3. **`agent1` и `agent1.analytics` — одна группа** «Сравнение и выводы» (тумблеры аналитики внутри
   подразделом). Заголовка «Сравнение и выводы: срезы отчёта» больше нет.
4. **Новая группа «Конкуренты в анализе»** (динамическая, не скаляры): истинный список из
   `01-competitor-watch/config/clients/<client>.yaml → competitors[]` + форма ручного добавления +
   удаление, ниже — кандидаты автоподбора с «Добавить в анализ»/«Отклонить».
5. **Новая группа «Отправка отчёта»**: `delivery.auto_send` («отправлять в запланированное время»),
   `delivery.channels` и кнопка «Отправить отчёт на почту сейчас».
6. **Метрики карточки Агента 1** вместо задач/токенов/расхода: «конкурентов в анализе» (число движка),
   «с данными», «лотов проанализировано», «самый дешёвый лот». Нет данных — «данных нет», не 0.

## Что НЕ показывать в карточке агента

`schedule.*`, `model.*`, `priority.*`, `limits.*`, `source_agent.*` — системные для сервиса
(расход токенов, рубли, параллельность, ретраи). В карточке Агента 1 они не редактируются;
остаются в YAML и доступны в разделе системных настроек.

## Правила реализации (обязательны для панели и движка)

1. Имена полей и групп менять нельзя ни одной стороне отдельно — контракт один на всех.
2. Поле, показанное в панели, обязано читаться движком; иначе поле не показывать.
3. Поле, отсутствующее в YAML, работает по дефолту из этой таблицы, и панель честно
   показывает «значение по умолчанию, в файле не задано».
4. Неизвестные ключи в YAML не терять и не подставлять молча — выводить предупреждение.
