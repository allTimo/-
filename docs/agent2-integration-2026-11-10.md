Почему токен вставляется вручную: у приложения Яндекса «Для доступа к API или отладки» `redirect_uri`
зафиксирован (`https://oauth.yandex.ru/verification_code`) и не меняется — токен показывается на странице
Яндекса, вернуть его в панель автоматически нельзя. Поэтому: кнопка → вход и согласие → копирование токена → вставка в панель → проверка.

Client ID приложения (сохранён 10.11.2026): `58a31736…7c45`. Client secret для этого потока не нужен
(`response_type=token`) и в проект не записан.

Приёмка: `GET /api/direct/accounts` отдаёт `clientIdSet: true`; блок в отрендеренном DOM содержит
«OAuth-приложение настроено» и «Подключить кабинет»; фейковый токен получает от живого Директа
`ошибка API 53: Недействительный OAuth-токен` и **не сохраняется**; замороженный `ux-check` — OK 21 / провал 0;
`verify-data` — exit 0; 138 тестов скиллов OK.

## Секреты и API по инструкции пользователя (10.11.2026)

Модуль приведён к правилам: токен — только из окружения (`.env`), в чат/логи/отчёты не выводится.

| Что | Как |
|---|---|
| Основной токен | `YANDEX_OAUTH_TOKEN` (приоритет). Устаревшее `YANDEX_DIRECT_TOKEN` читается как запасной вариант — старые записи не ломаются. |
| Директ API v5 | `https://api.direct.yandex.com/json/v5/{service}`, заголовок `Authorization: Bearer …`; `Client-Login` — только если задан `YANDEX_DIRECT_CLIENT_LOGIN`. |
| Метрика | `https://api-metrika.yandex.net/management/v1/counter/{YANDEX_METRICA_COUNTER_ID}`, заголовок `Authorization: OAuth …` (не Bearer); токен — `YANDEX_METRIKA_TOKEN` или основной. |
| Где хранятся | Только `.env` (вне репозитория) и `00-admin/config/direct-accounts.local.json` (вне репозитория, 0600) для кабинетов, привязанных из панели. |
| Проверка | `get_metrika_counter()` и `check_access()` (поле `metrika`, только когда задан счётчик). 144 теста, включая контракт заголовков и приоритет переменных. |

Аудит 10.11.2026: Client secret в файлах проекта **не найден** (grep по репозиторию и логам DSH);
Client ID — публичный, лежит в `.env.example`-подобном хранилище панели. Секрет, показанный в чате,
следует перевыпустить в oauth.yandex.ru.

## Честные ограничения

1. **Живой Директ не проверялся**: токена нет, `Campaigns.get`/Reports работают только на мок-транспорте. Первый живой шаг — `--check` с токеном.
2. **Reports асинхронный**: 201 = «отчёт готовится», модуль отдаёт `pending`, а не выдумывает данные. Песочница Reports не поддерживает (честный `error`).
3. **Модуль только читает**: ставки, бюджеты, создание и включение кампаний не выполняются — по регламенту проекта это отдельное подтверждённое действие.
4. **`web_search` в этой сессии недоступен** (HTTP 402 Insufficient Balance у провайдера поиска); лимиты объявлений сверены через `web_fetch` по документации Директа, ссылки записаны в комментарии `ads.yaml`.
5. **D6** (плавающий FAIL расхождения по сессии) — существовавший дефект, не от этих работ.
