# Агент 1: «ЖК для наблюдения» и автоподбор конкурентов в радиусе

Договорённость от 01.11.2026. Пользователь задаёт **свой ЖК**, агент сам подбирает конкурентов **в радиусе до 10 км** (радиус настраивается).

## 1. Что задаёт пользователь

В карточке Агента 1 (блок «Тонкие настройки») появляется группа **«ЖК для наблюдения»**:

| Поле | Обязательное | Что это |
|---|---|---|
| Название ЖК | да | «ЖК «Свет»» |
| Адрес | да | «Москва, ул. …» — нужен для определения координат |
| Ссылка на сайт ЖК | нет | для сбора данных о своём проекте |
| Координаты | нет | если пусто — агент определит по адресу сам |
| **Радиус поиска конкурентов, км** | да | по умолчанию **10** |
| Класс/сегмент | да | бизнес, премиум (можно несколько) |
| Диапазон цены за м² | нет | отсекает нерелевантных |
| Источники поиска | да | Циан, Авито, Яндекс Недвижимость, Домклик, веб-поиск |
| Максимум кандидатов | да | по умолчанию 20 |

## 2. Как агент подбирает

1. **Координаты своего ЖК**: берёт из поля, если заданы; иначе геокодирует по адресу (открытый геокодер OSM/Nominatim, при наличии ключа — Яндекс.Геокодер).
2. **Поиск кандидатов в радиусе**: проходит по площадкам из списка (публичные страницы, **без логина**) и собирает проекты новостроек; дополнительно — веб-поиск по формуле «новостройки <район/метро> бизнес-класс».
3. **Фильтр по релевантности**: класс совпадает; цена за м² попадает в диапазон (если задан); расстояние ≤ радиуса (считается по координатам, формула гаверсинуса).
4. **Список кандидатов** сохраняется в `01-competitor-watch/data/candidates/<project-id>.json`:
   name · developer · class · **distance_km** · price_per_m2 (если известна) · sources[] (платформа + ссылка) · found_at · confidence · status (candidate | approved | rejected).
5. **Решение пользователя**: в панели у каждого кандидата кнопки «Добавить в конкуренты» и «Отклонить». Добавленные попадают в `agent1.competitors` клиентского конфига и участвуют в следующих прогонах. Отклонённые запоминаются, чтобы не предлагать снова.

### 5.1. Разделение файлов (обязательно)

| Файл | Кто пишет |
|---|---|
| `data/candidates/<project-id>.json` — список кандидатов | **только движок** |
| `data/candidates/<project-id>.decisions.json` — решения пользователя | **только панель** |
| `config/clients/<client-id>.yaml` — подтверждённые конкуренты | панель (по действию пользователя) и agent1-workspace (первоначальный файл); движок **только читает** |

**Требования к движку:**
1. В каждой записи кандидата обязательно проставлять **`id`** (стабильный, например слаг «название-застройщик»): панель использует его как ключ решения, и тогда ключи не «плывут» при переименовании проекта.
2. При каждом прогоне читать `<project-id>.decisions.json` и применять решения: `approved` показывать как подтверждённого конкурента (и предлагать перенести в конфиг), `rejected` — больше не предлагать.
3. Сам файл решений **не писать** (только читать) — его ведёт панель.

## 3. Честные ограничения (обязательно к показу)

- Геокодирование по адресу может ошибаться (особенно по «Москва, ул. …» без номера дома) — если точность низкая, агент помечает это и просит уточнить координаты.
- Часть площадок не отдаёт координаты и цены на публичных страницах: тогда кандидат попадает в список **без расстояния или без цены** с пометкой «данных нет», а не с выдуманными числами.
- Расстояние считается по прямой между точками, точность ±0,5 км — для отбора достаточно, для юридических целей нет.
- Автоподбор **не заменяет** решение человека: список приходит на подтверждение.

## 4. Где что лежит

| Что | Где |
|---|---|
| Настройки агента (ЖК, радиус, сегмент) | `registry/agent-settings/agent-1-competitor-watch.yaml`, группа `agent1.watch` |
| Список кандидатов | `01-competitor-watch/data/candidates/<project-id>.json` |
| Подтверждённые конкуренты | клиентский конфиг `01-competitor-watch/config/clients/<client-id>.yaml`, поле `competitors` |
| Журнал поиска | `registry/runs.jsonl` (тип прогона `discovery`) |
