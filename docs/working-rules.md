# Правила работы (введены пользователем 01.11.2026)

## 1. Останавливаемся после каждой задачи и показываем список

После выполнения задачи Lead **останавливается** и показывает пользователю **список оставшихся задач** (с кратким смыслом по каждой), после чего пользователь **сам выбирает следующую**. Не начинаем следующую задачу «по инерции», даже если она логично вытекает из предыдущей.

Порядок:
1. Задача сдана исполнителем → Lead проверяет сам.
2. Lead показывает: что сделано, что осталось (списком), какие есть предложения — и ждёт выбора.
3. Только после выбора пользователя задача берётся в работу.

## 2. Границы запроса: только интерфейс

Текущая тема — **аудит и улучшение ИНТЕРФЕЙСА**. Всё, что касается продаж, лендинга, захвата лидов, оплат, юридических документов и каналов связи, в этот объём **не входит** и отложено до отдельного запроса пользователя.

Уточнение по аудиту пути пользователя (docs/customer-journey.md): из него берём **только интерфейсные части** (как выглядит и ведёт себя поверхность «Клиент», онбординг, понятность экранов). Разделы про заявки, оплату, лендинг и продажи — **парковка**.

## 3. Что значит «интерфейс»

- экраны панели: разделы, блоки, таблицы, кнопки, тумблеры, вкладки, режимы;
- поведение элементов: клик меняет содержимое, состояние сохраняется, есть отклик;
- читаемость и понятность: тексты, подписи, подсказки, пустые состояния, ошибки;
- честность данных в интерфейсе: источник, дата, «оценка», «данных нет» вместо нуля;
- удобство: сколько кликов до частой задачи, поиск, фильтры, сортировка, клавиатура;
- целостность версии: пользователь не видит старую версию после обновления.

## 4. Приёмка интерфейса

Любое изменение интерфейса проходит **замороженный** поведенческий автотест (dashboard/ux-check.mjs, версия фиксируется) плюс проверку версии интерфейса и данных. Файл теста меняется только через Lead.
