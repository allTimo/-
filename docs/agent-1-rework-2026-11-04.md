# Переработка Агента 1 в панели — контракт v2 (Lead, 04.11.2026)

Источник: запрос пользователя (4 пункта, дословно в §1). Этот файл — единственный контракт для
движка, сервера панели, сборщика и интерфейса. Имена групп/полей/ключей менять нельзя одной стороной.

## 1. Запрос пользователя (что именно чиним)

1. Тонкие настройки дублируют друг друга — проверить все дубли и оставить **одну вкладку**.
2. Автоподбор конкурентов по радиусу **не работает**. Должно быть две настройки: (а) сбор конкурентов
   по радиусу, (б) ручной список сайтов конкурентов, который пользователь ведёт сам. Оба списка
   **объединяются** и становятся предметом анализа. Итоговый список виден в панели, редактируется
   (добавить/удалить), он **динамический**: добавили — конкурент в анализе, удалили — ушёл из анализа.
   Этот список — **истина** для дальнейшего анализа конкурентов.
3. Вместо «задач / токенов / расходов» карточка Агента 1 показывает: **сколько конкурентов в аналитике**,
   **сколько лотов проанализировано**, **цену самого дешёвого лота**.
4. Отчёты **не отправляются** при каждом обновлении данных или изменении настроек. Отправка — только
   по кнопке/тумблеру в панели или в запланированное время.

## 4. Метрики карточки Агента 1 (вместо задач/токенов/расхода)

Только для `agent-1-competitor-watch`; у остальных агентов метрики не меняются.

| Плитка | Значение | Откуда | Честность |
|---|---|---|---|
| «конкурентов в анализе» | N | `metrics.competitorsInAnalysis` (число движка) | если метрики нет — «данных нет», не 0 и не размер списка |
| «с данными» | M из N | `metrics.competitorsWithData` из того же N | M < N — это норма, показываем оба числа |
| подсказка к предыдущим двум | «в списках L, без источника K» | `truth.competitors` / `truth.withoutSource` | разница «в списке 21 / в анализе 19» видна словами, а не спрятана |
| «лотов проанализировано» | lots | `metrics.lotsAnalyzed` | нет данных → «данных нет» |
| «самый дешёвый лот» | ₽ | `metrics.cheapestLotRub` | нет данных → «данных нет» |

**Уточнение Lead 04.11.2026 (после дефекта D-CARD):** плитки карточки никогда не берут размер
истинного списка как число «в анализе» — только метрики движка; размер списка показывается отдельной
подсказкой. Причина: список и анализ — разные множества (записи без источника в анализ не попадают).

Убирать цифры токенов/расхода **только в карточке Агента 1**; вкладка «Расходы» не меняется.

## 5. Контракт данных (обязателен для всех сторон)

### 5.1. Истинный список конкурентов

- Хранение: `01-competitor-watch/config/clients/<client-id>.yaml`, поле `competitors[]` — **истина**.
- Запись/удаление — панель, атомарно (temp+rename) с копией `.bak-<timestamp>`; движок — только чтение.
- Движок обязан: брать цели анализа **только** из этого списка (столько, сколько в нём записей);
  удалённая запись в анализ больше не попадает; добавленная с `site` или `platforms` — попадает
  в ближайшем прогоне. Запись без `site` и без ссылок площадок анализу недоступна — это должно быть
  видно в панели словами «без источника — в анализ не попадает», а не молчанием.
- Ручное добавление из панели пишет запись вида:
  `- { id: <слаг>, name: "<название>", developer: "<застройщик>", class: "<класс или пусто>", site: "<URL сайта или пусто>", platforms: { cian: "", avito: "", yandex_realty: "", domclick: "" }, source: "вручную", added: "ГГГГ-ММ-ДД" }`
- Кандидаты автоподбора остаются зоной движка: `data/candidates/<project-id>.json`;
  решения — зона панели: `data/candidates/<project-id>.decisions.json`.

### 5.2. Эндпоинты панели (dashboard/serve.mjs)

| Метод | Путь | Тело | Что делает |
|---|---|---|---|
| POST | `/api/agent1/discover` | `{ project? }` | **реально запускает** `discover_competitors.py` (проект/радиус из `agent1.watch`), возвращает честный итог: `ok`, `ran`, `exitCode`, `stdoutTail`, `message`, `summary`. Никаких выдуманных кандидатов; при `DASHBOARD_ACTIONS_DRY_RUN=1` — сухой прогон |
| POST | `/api/agent1/competitor-list` | `{ client, action: 'add'\|'remove', id\|name, ... }` | add/remove записи в клиентском конфиге (истина); ответ: `ok`, `message`, `competitorsCount`, `backup` |
| POST | `/api/agent1/candidate` | как сейчас | approve → конфиг + decisions; reject → decisions (не трогать конфиг) |
| POST | `/api/agent1/send-report` | `{ client }` | **явная** отправка последнего готового отчёта на белый список; возвращает `ok`, `sent[]`, `message` |
| POST | `/api/agent-settings/set` | как сейчас | плюс `delivery.auto_send`, `delivery.channels` разрешены для `agent-1-competitor-watch` |

`REFRESH_AFTER_WRITE` остаётся: правка настроек пересобирает **данные панели**, но **не отправляет почту**.

### 5.3. Ключи JSON для панели

`dashboard/public/data/competitor-analytics.json` (зона `collector/lib/competitor-analytics.mjs`):

```
clients[]: {
  clientId, fileName, generatedAt,
  truth: { competitors: N, withData: M, withoutSource: K, list: [{ id, name, developer, klass, site, platforms, hasSource }] },
  metrics: { competitorsInAnalysis: N, competitorsWithData: M, lotsAnalyzed: L|null, cheapestLotRub: R|null },
  ...существующие byCompetitor / bySource / dynamics / promosNew / forecast / dataStatus
}
totals: { competitors, withData, lotsOnSale, lotsAnalyzed, cheapestLotRub, sources, promosNew }
```

Движок обязан отдать те же числа в `analytics-<дата>.json` (`metrics`), чтобы панель не считала их сама.
«Самое дешёвое» = минимум `price_rub` по лотам, попавшим в анализ после фильтров селекции; нет лотов → `null`.

### 5.4. Почта: режимы отправки

- Новый аргумент движка: `--email-mode {never|always|on-request}` (по умолчанию **`never`** для
  ad-hoc прогонов).
- Письмо уходит, только если одновременно: `email-mode=always|on-request` **и**
  `delivery.channels` содержит `email` **и** `delivery.auto_send: true` (для `always`).
- Плановый прогон (`install/agent1-weekly.cmd`) передаёт `--email-mode always`.
- Кнопка панели «Отправить отчёт сейчас» → `/api/agent1/send-report` (режим `on-request`).
- Любой прогон «Обновить данные» / сохранение настроек **не отправляет** ничего.
- Причина отказа всегда печатается словами: «письмо не отправлено: канал email выключен»,
  «письмо не отправлено: автоотправка выключена — нажмите «Отправить отчёт сейчас»».
