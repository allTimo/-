# Шаг 1A: панель как рабочее место маркетолога — 09.11.2026

Основание: решение пользователя 09.11.2026 — **сначала маркетинговая панель для работы на себе и клиентах
(проверка агентов), бизнес-контур (подписки, услуги, кэшбэк, финмодель) — после**. Вариант выбран
пользователем из четырёх предложенных: **A + B пошагово**, «все агенты» включают Агентов 1–4
(Агенты 3–4 делаются с нуля, отдельным этапом).

Предыдущий порядок (зафиксирован в `docs/roadmap.md`) ставил раньше каркас сервиса и биллинг —
он этим решением сдвинут: панель-инструмент важнее, потому что без рабочих агентов продавать нечего.

## Важное для следующей сессии

1. `nav.json` — кэш: после правки `nav.yaml` обязательна пересборка `node dashboard/collector/collect.mjs`.
2. Панель не переживает перезапуск DSH — поднимать вручную (`node dashboard/serve.mjs`, порт через `DASHBOARD_PORT`).
3. Шаг 1B (следующий): **стенд агентов** — 4 карточки, вход (клиент/ЖК/бюджет), запуск, лог, история прогонов,
   стоимость и время прогона. Сейчас карточки агентов рисует один код (`app.js:1048+`) с навесным блоком Агента 1
   (`app-views15.js`), «скоро»-вкладки — `config/agents-tabs.yaml`.
4. Демо-режим снимается, когда реестр (`registry/subscriptions.yaml`, `registry/invoices.yaml`, `registry/ad-budgets.yaml`)
   перейдёт на реальные записи: флаги `demo` в `service.mjs` и `ads.mjs` — единственное место для снятия.
