# Патч C: `dsh-scrape-webpage` — честное сообщение вместо падения

Дата: 04.11.2026. Согласовано пользователем ранее («4) да»). Правка **вне рабочей области** —
в профиле DSH, поэтому применяется только с подтверждением.

## Зачем

Инструмент `scrape_webpage` падает на любом URL с сырой ошибкой:

```
Не удалось загрузить страницу: Не удалось выполнить команду: shell.run is not a function
```

Причина (диагноз — `docs/scrape-webpage-diagnosis-2026-11-04.md`): `lib/index.js:97` берёт
`ctx.get('shell')`, проверяет только «службы нет вовсе», а затем `lib/fetch.js:34` вызывает
`shell.run(...)`. На хосте **0.2.1-rc.5** служба `shell` есть, но метода `run` в ней нет —
отсюда `TypeError` вместо понятного сообщения. В `lib/index.js:99` у автора уже есть
человеческая формулировка для случая «службы нет» — патч доводит её до случая «служба не той формы».

## Файл и точная правка

Файл: `C:\Users\Артем\.dsh\profiles\desktop\node_modules\dsh-scrape-webpage\lib\fetch.js`

Строки 32–37 сейчас:

```js
    let result = null
    try {
      result = await shell.run(shell.resolve(request))
    } catch (err) {
      throw new Error('Не удалось выполнить команду: ' + String((err && err.message) || err))
    }
```

Станут:

```js
    let result = null
    if (typeof shell.run !== 'function') {
      // Хост может отдать службу shell без run() (проверено на 0.2.1-rc.5): без этой
      // проверки наружу уходил TypeError «shell.run is not a function» вместо причины.
      throw new Error('Служба shell не предоставляет run() — загрузить страницу этим способом нельзя; нужен web-провайдер или чтение страницы движком агента')
    }
    try {
      result = await shell.run(shell.resolve(request))
    } catch (err) {
      throw new Error('Не удалось выполнить команду: ' + String((err && err.message) || err))
    }
```

Поведение при исправной службе не меняется: добавлена только проверка формы перед вызовом.

## Порядок применения (я выполняю, если скажете «патч применяй»)

1. Копия файла рядом: `lib/fetch.js.bak-cw-<дата-время>` (в `lib/` уже лежат `.bak-ru-*` от локализации — не трогаю их).
2. Вставка проверки (правка только этих строк, остальной файл не переписывается).
3. Проверка: `node --check lib/fetch.js`.
4. Проверка по существу: вызов `scrape_webpage` на любом URL — ожидается понятное сообщение
   «Служба shell не предоставляет run()…» вместо `shell.run is not a function`.
5. Откат — просто вернуть файл из копии (одна команда).

## Честные оговорки

* Патч **не делает инструмент рабочим** — он делает отказ понятным. Читать страницы конкурентов
  продолжает движок Агента 1 (анонимный HTTP, при блокировке — Chrome с вынужденным `--no-sandbox`),
  и это уже проверено на живых сайтах.
* Правка затрётся при обновлении плагина из маркета — тогда её нужно повторить или дождаться
  исправления у автора (`github.com/131CDA1/dsh-scrape-webpage`).
* Плагин объявляет `allowed-tools`-подобных требований к `shell` в манифесте и **не объявляет
  `engines.dsh`**, поэтому маркет не мог предупредить о несовместимости.
