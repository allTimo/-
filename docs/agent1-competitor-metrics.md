## 2. Честно про Росреестр и ЕИСЖС

**Обновлено 01.11.2026 (после проверки через браузер).**

Что проверено и что получено:

| Источник | Обычный HTTP | Chrome (CDP, чистый профиль, без логина) | Итог |
|---|---|---|---|
| **наш.дом.рф (ЕИСЖС)** | ошибка TLS | без флага сертификата Chrome отдаёт СВОЮ страницу ошибки; с `--ignore-certificate-errors` сайт отвечает **«Сайт xn--80asehdb.xn--p1ai отключен»** | **источник отключён** — официальных корпусов/квартир/ДДУ получить нельзя |
| **rosreestr.gov.ru** | ошибка TLS (self-signed в цепочке) | с `--ignore-certificate-errors` открывается (title «Главная страница», 62 ресурса) | **страница доступна**, но публичных данных о корпусах/ДДУ конкретного ЖК там нет |

Важный урок: страница-ошибка Chrome весит >100 КБ, и по размеру её легко принять за данные. В движке
появилась проверка (`platforms.is_chrome_error_page`) — ошибка сертификата больше не считается успехом.
Ранее опубликованный вывод «ЕИСЖС открылся (138 КБ)» **был ошибочным**: это была страница ошибки Chrome.

Что сделано в движке (готово к моменту, когда источник вернётся):
* `platforms.ignore_cert_errors` — явный флаг для Chrome (сеть подменяет сертификат), применяется только к чтению публичных страниц;
* `competitor_profile.parse_eiszhs_card` — разбор карточки проекта: корпуса (адрес, стадия «введён/строится», срок ввода, готовность), всего квартир, зарегистрированные ДДУ;
* `match_eiszhs_project` — сопоставление нашего ЖК с карточкой по названию (+ застройщик/адрес); при неоднозначности пишем **«требует подтверждения»** и не угадываем;
* метрики профиля: `corpi_total`, `corpi_built`, `corpi_under_construction`, `flats_total`, `ddu_registered` (источник ЕИСЖС, метод dom), derived `sold_share_official_pct` = ДДУ / всего квартир;
* вежливый режим: кэш статуса источников на сутки (`competitor-profiles/source-status.json`), лимит обращений за прогон, пауза между запросами;
* когда источника нет — **все метрики null** с причиной («официальные данные получить нельзя: ЕИСЖС — источник отключён»), а не нули и не наши оценки.

Что нужно, чтобы блок заработал: доступность наш.дом.рф из этой сети (сейчас он отключён) либо
официальный доступ к API ЕИСЖС/Росреестра. Тогда те же метрики заполнятся без изменений в коде.

Прежняя формулировка («оба домена недоступны») устарела — она относилась только к обычному HTTP.

Что делаем вместо этого:
1. **Обходной путь 1 — браузер.** Попробовать через Chrome по CDP (как с Авито) — иногда TLS-фильтр обходится браузером.
2. **Обходной путь 2 — сайт застройщика.** Многие застройщики публикуют шахматку/выбор квартир, где видны проданные и забронированные лоты. Это законный публичный источник.
3. **Косвенная оценка (работает всегда):** считаем уход лотов из продажи между неделями — это нижняя оценка продаж и снятий с продажи. Честно помечаем как оценку, а не как «данные Росреестра».

## 3. Мои идеи: что ещё считаем для стратегических решений

| Идея | Что даёт |
|---|---|
| **Скорость продаж** (ушедшие лоты в неделю) | темп, с которым конкурент реально продаёт |
| **Absorption rate** — доля проданного от объёма предложения | насколько проект «разошёлся» |
| **Прогноз распродажи** — месяцев до конца при текущем темпе | понимание дефицита и сроков роста цен |
| **Динамика цены входа** (минимальная цена) | самый ранний индикатор изменения политики цен |
| **Индекс цены** — цена конкурента / медиана района | дорого или дёшево относительно окружения |
| **Динамика предложения** (растёт/падает число лотов) | выход новых корпусов или распродажа |
| **Промо-давление** — сколько недель подряд идут акции, глубина | сила давления на спрос |
| **Структура по комнатности** (сдвиг в студии/малогабаритки) | смена продукта и целевой аудитории |
| **Средняя площадь** (уменьшается ли) | оптимизация продукта под цену входа |
| **Старт новых корпусов** (появление новых лотов/корпусов) | момент нового предложения — окно для наших акций |
| **Разрывы «мы vs конкурент»**: цена, площадь, срок сдачи | основание для собственного ценообразования и офферов |
| **Сезонность** (когда спрос выше, по накопленным неделям) | планирование бюджетов |
| **Риск-флаги**: резкий рост предложения, сброс цен, агрессивные акции | тревога в панели до того, как это заметят все |

## 5. Правила честности

- Нет данных — пишем «данных нет» и почему (нет на странице / источник закрыт), а не ноль и не оценку.
- Оценки (например косвенные продажи по уходу лотов) помечаем словом «оценка» и объясняем метод.
- Данные Росреестра/ЕИСЖС не подменяем своими: пока недоступны — так и говорим.
- Каждая метрика знает свой источник и дату сбора (видно в панели).

### 6.2. Звонки, конверсия, визиты в офис продаж

**Этих данных в открытых источниках нет.** Ни застройщики, ни площадки их не публикуют: это внутренняя аналитика (CRM, коллтрекинг, записи в офис).

Что можно и нельзя:
- **Нельзя:** количество звонков, конверсия в сделку, число визитов, стоимость лида у конкурента — **в открытых источниках не существует**.
- **Косвенные признаки (только как «оценка», с оговоркой):** наличие и активность онлайн-записи в офис продаж, число и свежесть отзывов, ответы застройщика, скорость публикации новых лотов, темп ухода лотов.
- **Правило:** если данных нет — в панели «данных нет: источник не публикует», без цифр.

### 6.3. Приоритет по Росреестру (решение пользователя)

Главная задача — **вытащить максимум данных максимально простым способом; самое важное — продажи**. Порядок попыток:
1. альтернативные маршруты к ЕИСЖС/Росреестру (другие хосты и API-эндпоинты, мобильные API, открытые наборы данных ДОМ.РФ);
2. данные продаж с сайтов застройщиков (шахматка: продано/забронировано) — уже реализуется;
3. косвенная оценка по уходу лотов (наш мониторинг) — помечается «оценка»;
4. платные источники (bnMAP.pro, Циан.Аналитика) — по решению пользователя.

### 6.4. Что фактически выяснено по маршрутам (проверено 01.11.2026)

Инструмент: `01-competitor-watch/scripts/sales_sources.py` (сохраняет вердикт в
`data/clients/<client-id>/sales-sources.json`). Проверка шла обычным HTTP, **с отключённой
проверкой сертификата** (сеть подменяет цепочку: у госсайтов самоподписанный корень) — режим
явный и опциональный, в метрике фиксируется.

| Маршрут | Результат | Вывод |
|---|---|---|
| ЕИСЖС: корень https | **HTTP 503 Service Temporarily Unavailable** | сервис недоступен на стороне сервера, это не наша блокировка |
| ЕИСЖС: корень http | **HTTP 503** | то же |
| ЕИСЖС: `/api/kn/object`, `/api/v1/objects`, `/сервисы/api/kn/object` | **HTTP 503** | JSON-эндпоинты недоступны вместе с сайтом |
| ЕИСЖС: мобильный хост `m.наш.дом.рф` | DNS не разрешается | мобильной версии нет |
| **ДОМ.РФ: дом.рф/аналитика** | **HTTP 200**, 110 КБ, **29 показателей** | ✅ открытый источник работает |
| Росреестр: `rosreestr.gov.ru/api/` | HTTP 403 | API требует авторизации/договора |
| Сайты застройщиков (ПИК, Самолёт) | HTTP 401 | закрыты для автоматических запросов |

Что даёт ДОМ.РФ (уровень «рынок», не по конкретному ЖК): «Выдача ипотеки — 788 тыс. кредитов»,
«Ставка по ипотеке — 18,76%», «Индекс цен на жильё — +5,9%», новости «Продажи новостроек» за
сентябрь 2026 г. и доля расторгнутых ДДУ. Всё с датой сбора, ссылкой и пометкой уровня.

**Вердикт по продажам конкретного ЖК:** официальные ДДУ/квартиры по проекту получить нельзя —
ЕИСЖС не работает, API Росреестра закрыт. Поэтому в профилях остаётся `ddu_registered = null`
с причиной, а рыночные показатели продаж идут отдельным блоком из ДОМ.РФ. Косвенная оценка по
уходу лотов сохраняется и помечается «оценка». Когда ЕИСЖС вернётся, код разбора карточки уже
готов и метрики заполнятся без изменений.
