  **только** JSON, который надо было составлять руками.

## Что сделано

### `01-competitor-watch/scripts/search_results.py` — новый модуль

Принимает то, что оператор реально может сохранить, и превращает в записи кандидатов
(контракт `build_candidates`: `name`, `url`, `source`):

| Вход | Разбор |
|---|---|
| ответ Serper (`{"organic": [{title, link, snippet}]}`) | `parse_serper()` |
| сохранённая страница выдачи (HTML) | `parse_html()` — пары «ссылка + видимый заголовок» |
| список ссылок текстом или markdown | `parse_text()` |
| прежний JSON движка (`[{...}]` или `{"results": [...]}`) | проходит как есть (совместимость) |

Правила честности:

* агрегаторы и соцсети (Циан, Авито, Домклик, Яндекс, 2ГИС, VK, Дзен, Википедия и др.) в
  кандидаты **не** попадают: нужен сайт застройщика;
* относительные ссылки и `javascript:` игнорируются, повторы по адресу схлопываются;
* ничего не додумывается: адрес и заголовок берутся из выдачи как есть.

### Предложения сайтов для клиента

`search_results.py --serp <файл> --client <id>` сравнивает выдачу с **уже известным списком
конкурентов клиента** и показывает предложение по каждому ЖК, у которого сайта нет:

```
Селигер Сити                 high     https://www.mr-group.ru/projects/zhk-seliger-siti
Дмитровское небо             high     https://www.lsr.ru/msk/zhilye-kompleksy/dmitrovskoe-nebo
Level Селигерская            high     https://level.ru/projects/seligerskaya
Сити Бэй                     medium   https://www.mr-group.ru/projects/zhk-seliger-siti
Level Южнопортовая           medium   https://level.ru/projects/seligerskaya
ЖК Нарвин                    none     —
```

Уверенность — доля значимых слов названия, найденных в заголовке результата:
все слова — `high`, половина — `medium`, ни одного — `none` и предложения нет.
**Запись не делается**: это предложение, решение принимает человек. Вывод ошибочный
(«Сити Бэй» → страница Селигер Сити) помечен `medium`, а не `high` — именно для того,
чтобы его проверяли глазами.

### Подключение к автоподбору

`discover_competitors.load_search_results(path)` теперь делегирует разбор в новый модуль:
`--search-results` принимает любой из перечисленных форматов. Прежнее поведение с JSON
сохранено, тесты движка на нём не менялись.

## Шаг 2: живые бэкенды поиска (`web_search.py`)

Добавлены оба адаптера, о которых шла речь в плане. `01-competitor-watch/scripts/web_search.py`:

| Бэкенд | Как работает | Условие |
|---|---|---|
| `serper` | POST `https://google.serper.dev/search`, ответ разбирается `search_results.parse_serper` | ключ `SERPER_API_KEY` (переменная окружения или `marketing-agents/.env`) |
| `cdp` | страница выдачи (`yandex` / `google`) открывается операторским Chrome через `platforms.cdp_html` и разбирается `search_results.parse_html` | запущенный Chrome (в песочнице недоступен) |
| `auto` | есть ключ — Serper, иначе Chrome | — |

Команды:

```powershell
python 01-competitor-watch/scripts/search_results.py --web-search serper --client client-svet
python 01-competitor-watch/scripts/search_results.py --web-search cdp --engine yandex --query "ЖК Селигер Сити официальный сайт"
```

Без `--query` запросы строятся из списка конкурентов клиента («<ЖК>» официальный сайт
застройщика Москва). Точки подмены для тестов — `post` (HTTP POST) и `cdp_html` (чтение
страницы браузером), поэтому весь код проверяется офлайн, без сети и Chrome.

Отказы честные, наружу исключений нет — проверено живьём в этой сессии:

```
--web-search serper → Serper: нет ключа SERPER_API_KEY — поиск не выполнялся
--web-search cdp    → CDP: Chrome не запустился — Chrome не поднял порт 9364 за 25 с
                      (в песочнице это ожидаемо; нужен запуск с полными правами)
```

## Шаг 3: перенос предложенных сайтов в конфиг клиента

Раньше шаг «предложили → записали» делался руками. Теперь есть явная команда, по умолчанию
**без записи**:

```powershell
# только показать, что было бы изменено (файл не трогается)
python 01-competitor-watch/scripts/search_results.py --serp serp.html --client client-svet --apply
# записать (с резервной копией client-svet.yaml.bak-<дата-время>)
python 01-competitor-watch/scripts/search_results.py --serp serp.html --client client-svet --apply --write
```

Правила:

* берутся только предложения с уверенностью `high` (`--include-medium` расширяет до `medium`);
* `--only "ЖК1,ЖК2"` ограничивает список;
* заполненный `site` **не перезаписывается** без явного `--force`;
* запись точечная: правится только строка `site` нужной записи (блочной или однострочной
  `- { ... }`), остальной файл не переписывается; перед записью создаётся `.bak`, после записи
  конфиг проверяется разбором движка.

Проверка на реальном `client-svet.yaml` (только показ) показала **0 изменений**: три предложения
подтвердили уже стоящие сайты (`skip_has_site`), а четвёртое («Дмитровское ш., 89» → ЛСР) убрано
после правки правила уверенности.

### Правка правила уверенности (ложное срабатывание)

На реальном списке конкурентов нашлось ложное срабатывание: «**Дмитровское ш., 89**» получало
уверенность `high` за одно совпавшее слово «Дмитровское» и предлагало сайт **другого** ЖК
(«Дмитровское небо»). Теперь, если у названия всего одно значимое слово, выше `medium` не поднимаем
и в примечании пишем «совпало одно слово названия — проверьте сайт вручную». Заодно это означает,
что по умолчанию (только `high`) такие предложения в конфиг не попадают.

Приёмка шага: `pytest 01-competitor-watch/tests -q` — **349 passed** (+6 тестов переноса),
CLI-прогон на реальном конфиге — код возврата 0, записей 0.

## Что осталось по задаче E (честно)

1. **Живой поиск не подтверждён на реальной выдаче**: нужен ключ `SERPER_API_KEY` либо запуск
   с полными правами, чтобы поднялся Chrome. Код обоих путей готов и покрыт тестами на
   заглушках; непроверенным остаётся именно живой ответ сервиса.
2. **Заполнение `platforms` у 12 конкурентов** (пункт 5 плана) теперь делается командой
   `--apply`/`--write`, но: (а) переносить пока нечего — нужна реальная выдача (см. пункт 1);
   (б) команда заполняет только `site` (официальный сайт), а ссылки на площадки
   (`cian`/`avito`/`yandex_realty`/`domclick`) по-прежнему заполняются вручную.
