# Разведка ReefAPI (Avito) — 2026-11-04

**Зачем:** решить, можно ли подключить `reefapi` как источник к движку Агента 1
(задача: подключить скиллы рынка Москвы по тематике продаж).
**Ключ:** хранится в `marketing-agents/.env` (`REEFAPI_KEY`), в репозиторий не попадает.
**Потрачено кредитов:** ~5 из 1 000 бесплатных.

## Что подтверждено живыми запросами

| Факт | Доказательство |
|---|---|
| Ключ рабочий | `POST /avito/v1/categories` → `ok: true`, `charged_credits: 1`, 592 категории |
| Нужен **браузерный User-Agent** | С программным UA запрос висит до таймаута; с браузерным — отвечает за 0,9–1,5 с |
| Ошибки бесплатны | Отказы приходят с `charged_credits: 0` |
| Эндпоинт для нас — `real_estate/search` (2 кредита) | У Avito 7 эндпоинтов, профильный — этот |
| `transaction` обязателен | Без него `MISSING_PARAM: missing: transaction` |
| Значения: `sale`, `rent_long`, `rent_daily`, `rent` | Из документации эндпоинта |
| **`market` + `transaction` вместе Avito отклоняет** | `UPSTREAM_HTTP`: «Avito refuses this filter combination… drop one of those filters» |
| Конверт ответа | `{ok, data, meta, error}`; `meta`: `charged_credits`, `latency_ms`, `record_count`, `stop_reason`, `request_id` |
| Ключи `data` для поиска | `listings`, `count`, `total`, `pageable_total`, `page`, `has_more`, `sort_applied`, `location`, `filters_applied`, `query_interpreted_as`, `sponsored_dropped`, `promoted_on_page` |

## Что блокирует подключение

**1. Скорость.** Замеры на живой выдаче Авито:

| Запрос | Ответ | Время |
|---|---|---|
| Валидационная ошибка | 0,9–1,5 с | ✔ |
| `/categories` (~1 МБ) | 592 категории | > 10 с (не влезает в лимит скилла) |
| Поиск «Жилой комплекс Селигер Сити» | 0 объявлений, 1,36 МБ | **68,7 с** |
| Поиск «Селигер Сити» без `market` | — | **> 280 с** (таймаут) |
| Каталог новостроек Москвы (`market: new_build`) | — | **> 150 с** (таймаут) |

Причина: ответы 1–1,4 МБ, а канал до Cloudflare медленный. Серверная задержка при этом
маленькая (`latency_ms` у служебного запроса — 20,8 мс), то есть тормозит передача.

**Следствие:** лимит скилла в 10 секунд для этого источника недостаточен физически.
Недельный прогон — это ~5 конкурентов × 2 клиента ≈ 10 поисков, то есть 10–45 минут
только на один источник, при лимите `priority.timeout_sec: 900` в настройках агента.

**2. Фильтр «новостройки» недоступен.** Avito отклоняет `market` вместе с `transaction`,
а `transaction` обязателен. Значит отобрать именно новостройки прямым фильтром нельзя —
только текстом запроса или последующей фильтрацией.

**3. Сопоставление по тексту ненадёжно.** Запрос «Жилой комплекс Селигер Сити» вернул
**0 объявлений** за 68,7 с и 2 кредита. Для нашей задачи (мониторинг конкретных
конкурирующих ЖК) это плохой признак: нужен подбор формулировок под каждый ЖК.

**4. Структура объявления не получена.** Ни один живой запрос не вернул непустой
`listings`, поэтому **имена полей лота неизвестны**. Без них нельзя написать корректный
маппинг в контракт `lots.csv` (нужны как минимум `price_rub`, `area_m2`, `rooms` —
движок отбрасывает лот без любого из них).

## Вывод

Подключить `reefapi` к недельному циклу **сейчас нельзя**: нет ни подтверждённого маппинга
полей, ни приемлемой скорости. Технически API рабочий и документация хорошая, но источник
не укладывается в бюджет времени недельного прогона.

## Решение пользователя (04.11.2026)

Подключить **только как режим разовой глубокой проверки по запросу**; в недельный цикл
НЕ включать. Риск по данным Авито через сторонний парсер принят пользователем.

Реализовано:

* `skills/real_estate/reefapi.py` — эндпоинт стал параметром, добавлена операторская
  функция `fetch_long()` с таймаутом до 600 с; обычный `fetch()` по-прежнему ≤ 10 с;
* `skills/runtime/http.py` — явный предел таймаута (`ceiling`): обычные скиллы
  остаются на 10 с, операторские режимы могут поднять его до `MAX_LONG_TIMEOUT`;
* `01-competitor-watch/scripts/reefapi_deep_check.py` — CLI разовой проверки: сохраняет
  сырой ответ и сводку в `01-competitor-watch/data/reefapi/`, **не пишет** в `lots.csv`;
* `registry/sources.yaml` — источник добавлен со `status: paused`, `enabled: false`;
* раздел в `00-admin/runbook.md`;
* тесты: 100, OK (предел 10 с для обычных скиллов сохранён и проверяется).

## Итог разведки: непустую выдачу получить не удалось

Сделано 8 обращений. Результаты:

| Попытка | Итог |
|---|---|
| `categories` | ✔ 592 категории, 1 кредит |
| `real_estate/search` без `transaction` | ✔ быстрый отказ `MISSING_PARAM` |
| `real_estate/search`, `market` + `transaction` | ✔ быстрый отказ `UPSTREAM_HTTP` |
| Поиск «Жилой комплекс Селигер Сити» | 0 объявлений за 68,7 с |
| Поиск «Селигер Сити» | таймаут > 280 с |
| Каталог новостроек Москвы | таймаут > 150 с |
| Повтор «Селигер Сити» | таймаут > 280 с |
| Через `reefapi_deep_check.py`, «новостройка Селигер Сити» | таймаут 420 с |

**Ни одного объявления получено не было**, поэтому имена полей лота по-прежнему
неизвестны. Прежде чем переходить к маппингу в `lots.csv`, нужно добыть хотя бы один
непустой ответ — вероятно, в другое время суток или с другого сетевого канала.

Диагностический файл `data/_probe-reefapi.json` удалён.
