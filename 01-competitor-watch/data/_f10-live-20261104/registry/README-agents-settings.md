# Тонкие настройки агентов

Каждый агент настраивается ОТДЕЛЬНЫМ файлом: `registry/agent-settings/<agent-id>.yaml`.
Это «основная настройка»: кроме общего тумблера включения у агента есть расписание, лимиты,
отчёт, доставка, алерты и ограничения. Правка из панели — атомарная, с копией `.bak-<timestamp>`;
обратимость проверяется по SHA-256, у каждого поля есть «вернуть как было».
В карточке Агента 1 видно не всё: только маркетинговые группы (см. «Что показывается
в карточке Агента 1»); системные группы остаются в файле.

## Общие группы (есть у всех агентов)

| Группа | Поля | Смысл |
|---|---|---|
| `schedule` | `enabled`, `days` (ISO 1–7), `time`, `frequency` (`daily`/`weekly`/`monthly`/`on-demand`), `timezone`, `only_on_new_data` | когда агент запускается сам |
| `model` | `name`, `limit_rub`, `limit_tokens`, `on_limit` (`pause`/`stop`/`warn`) | на какой модели работает и сколько ей позволено тратить |
| `priority` | `level` (`low`/`normal`/`high`), `max_parallel`, `timeout_sec`, `retries` | очередь, параллельность, таймаут, повторы |
| `report` | `formats` (`md`/`xlsx`/`csv`/`pdf`), `sections`, `language`, `branding` | что и на каком языке получается на выходе |
| `delivery` | `channels` (`telegram`/`email`/`vk`/`link`), `addresses`, `auto_send`, `copy_to` | куда отправлять и автоматически ли |
| `alerts` | `when` (`never`/`fail`/`low_data`/`always`), `price_threshold_pct`, `quiet_hours` | когда беспокоить и в какие часы молчать |
| `limits` | `skip_weekends`, `min_interval_hours`, `stop_switch` | «не запускать в выходные», «не чаще N часов», стоп-кран |

## Специфичные группы

### Источники: ОДИН источник правды

Решено 01.11.2026 — источники больше не живут в трёх местах:

| Где | Что задаёт | Кто главный |
|---|---|---|
| `01-competitor-watch/config/clients/<client-id>.yaml` | что **реально включено для конкретного клиента** | **ГЛАВНЫЙ источник правды** |
| `agent1.watch.sources` (в этом файле) | значения по умолчанию для **автоподбора конкурентов** | вспомогательный |
| ~~`agent1.sources`~~ | **УДАЛЁН** — дублировал и расходился | — |

Подтверждённые конкуренты **не хранятся** в настройках агента: они живут в клиентских
конфигах (`config/clients/<client-id>.yaml`, поле `competitors`). Заглушки из настроек убраны.

### `agent1.source_modes` — режим сбора по источнику

Единственное место, где задаётся доступность и способ сбора. Значения:
`http` (обычный запрос без логина) · `browser` (Chrome без логина) · `off` (выключен).

| Источник | Режим | Факт (проверено 01.11.2026) |
|---|---|---|
| `cian` | **http** | работает обычным HTTP без логина: 200 и реальные цены |
| `avito` | **browser** | работает через браузер без логина: движок взял 50 лотов |
| `yandex-realty` | **http** | требует ссылок уровня проекта — включаем с пометкой |
| `domclick` | **off** | закрыт (401/403) — держим выключенным |
| `developer-sites` | **http** | сайты застройщиков, обычный HTTP |

### `agent1` — у Агента 1 (мониторинг конкурентов)

| Поле | Смысл |
|---|---|
| `projects` | проекты клиента (id из `registry/projects.yaml`) |
| `competitors` | список конкурентов со ссылками: `{ name, url }` |
| ~~`sources`~~ | **удалено**: дублировало источники. Что включено для клиента — в клиентском конфиге; режим сбора — в `agent1.source_modes` |
| `source_modes` | режим сбора по источнику: http / browser / off (см. таблицу выше) |
| `price_threshold_pct` | порог изменения цены, % — ниже него изменение не считается значимым |
| `min_lots` | минимум лотов, иначе данные считаются неполными |
| `promo_words` | словарь акций для поиска промо в текстах |
| `collect_mode` | `http` — без браузера, `browser` — через Chrome без логина |
| `compare_depth_weeks` | на сколько недель назад сравнивать |
| `top_deals_count` | сколько лотов показывать в топах изменений (1–20, дефолт 5) |
| `watch.*` | «Охват и радиус»: свой ЖК, вокруг которого ищем конкурентов (`query`, `name`, `address`, `url`, `lat`, `lon`, `radius_km`, `klass`, `price_min_per_m2`, `price_max_per_m2`, `sources`, `max_candidates`) |
| `selection.*` | «Что анализировать»: маркетинговый срез лотов (см. раздел ниже) |
| `analytics.*` | тумблеры аналитики Агента 1 (см. раздел ниже) |

### `agent1.watch` — «Охват и радиус»

Все поля группы видны и правимы в карточке агента; `query` — название проекта или сайт,
по нему после сохранения запускается автоподбор. `radius_km` (дефолт 10) — радиус поиска,
`klass` — сегмент (`комфорт`/`бизнес`/`премиум`/`элит`), `max_candidates` — сколько конкурентов
берём в работу, `sources` — где искать (`cian`, `avito`, `yandex-realty`, `domclick`, `web-search`),
`price_min_per_m2`/`price_max_per_m2` — границы сегмента по цене за м².
Если `lat`/`lon` пусты, координаты определяются по адресу.

### `agent1.selection` — «Что анализировать»

Контракт: `docs/agent-1-marketing-settings-contract.md`, группа 2. Все 15 полей правимы из панели
и читаются движком. Пустое ограничение записывается как `0` — это «без ограничения», а не «данных нет».

| Поле | Тип | Значения / диапазон | Дефолт |
|---|---|---|---|
| `room_types` | list | `0` (студия), `1`, `2`, `3`, `4`, `5+` | все |
| `area_min_m2` | num | 0–400 | 0 (без ограничения) |
| `area_max_m2` | num | 0–400 | 0 (без ограничения) |
| `price_min_rub` | int | ≥ 0 | 0 (без ограничения) |
| `price_max_rub` | int | ≥ 0 | 0 (без ограничения) |
| `exclude_first_floor` | bool | — | false |
| `exclude_last_floor` | bool | — | false |
| `finishes` | list | `без отделки`, `white box`, `чистовая`, `с мебелью`, `unknown` | все |
| `only_active` | bool | — | true |
| `promo_only` | bool | — | false |
| `price_metric` | enum | `median` \| `mean` \| `min_max` | median |
| `outlier_guard` | bool | — | true |
| `outlier_same_price_min_lots` | int | 2–50 | 5 |
| `outlier_ppm2_min` | int | ≥ 0 | 150000 |
| `outlier_ppm2_max` | int | ≥ 0 | 800000 |

Группа `room_types` живёт ТОЛЬКО здесь: в `agent1.watch` её нет и быть не должно.

### `agent1.analytics` — тумблеры аналитики

Имена полей фиксированы: их читают панель и движок. Все значения булевы.

| Поле | Смысл |
|---|---|
| `enabled` | общий выключатель аналитики |
| `lots_all_on_sale` | показывать все лоты в продаже |
| `price_dynamics` | динамика цен (неделя-к-неделе) |
| `promos` | раздел акций и промо |
| `new_promos_only` | только новые акции |
| `dedup_promos` | схлопывать дубли акций |
| `developers_sites` | аналитика по сайтам застройщиков |
| `forecast` | прогноз |

## Что показывается в карточке Агента 1

В карточке Агента 1 блок «Тонкие настройки» регулирует ТОЛЬКО маркетинговые значения —
три группы: **«Охват и радиус»** (`agent1.watch`), **«Что анализировать»** (`agent1.selection`)
и **«Сравнение и выводы»** (`agent1` + `agent1.analytics`).

Системные группы `schedule`, `model`, `priority`, `limits`, `source_agent` в карточке агента
**не показываются** (расход токенов и рубли, параллельность, ретраи — не маркетинговая настройка).
Они остаются в этом YAML как есть. Дополнительно в карточке видны «Домены конкурентов»
(карта `domain → ключ проекта`, нужна для сопоставления бюджетов) и «Подбор конкурентов».

Клик по самой карточке агента больше не открывает боковое меню — для подробностей есть
отдельная кнопка «Детали».

### Доставка: email

`delivery.channels` принимает `telegram`, `email`, `vk`, `link`; адреса — в `delivery.addresses`,
автоотправка — `delivery.auto_send`. У Агента 1 сейчас включён только `email`: Telegram-транспорта
в движке нет, поэтому канал не заявляется (решение пользователя 04.11.2026).

SMTP-транспорт почты задаётся глобально в `00-admin/config/settings.yaml` → `delivery.email`:
`smtp_host`, `smtp_port` (465), `smtp_user`, `smtp_password_env` (имя переменной окружения
с паролем, по умолчанию `DSH_SMTP_PASSWORD`), `from`, `use_ssl`. **Секреты в файлах не хранятся** —
пароль берётся из переменной окружения. Общий режим отправки — `delivery.send_mode: auto`.

### `source_agent` — у агентов-источников

`rate_limit_per_min` (запросов в минуту), `pause_ms` (пауза между запросами),
`max_pages` (максимум страниц), `timeout_sec`, `stop_on_block` (остановиться при блокировке),
`use_browser` (использовать ли браузер).

## Файл-заготовка

Если у агента `status: stub`, поля показываются, но **неактивны и сохранять их нельзя** —
так у Агента 2, 3 и 4: «настройки появятся вместе с агентом».

## Проверки

`verify-data.mjs` проверяет: настройки читаются, значения в допустимых диапазонах
(часы, дни недели, неотрицательные лимиты), у каждого агента из `agents.yaml` есть свой файл,
а эффективные настройки совпадают с содержимым файла. Отдельный регресс сверяет группу
`agent1.selection` сразу в трёх местах: схема панели (`dashboard/serve.mjs`), нормализация
сборщика (`collector/lib/agent-settings.mjs`) и контракт `docs/agent-1-marketing-settings-contract.md`
(имена и типы полей, отсутствие `room_types` в `agent1.watch`). Обратимость правки — по SHA-256.
Сквозная запись поля из новой группы проверяется офлайн-тестом
`dashboard/_ux-harness/test-selection-e2e.mjs`; рендер карточки — `_ux-harness/test-agent1-card.mjs`.
