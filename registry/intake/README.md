# Приём задач: голос и текст из Яндекс Телемоста

Здесь встреча превращается в задачи реестра: вы кладёте запись или расшифровку в папку,
запускаете одну команду и получаете задачи в registry\tasks\<YYYY-MM>.yaml.

У Телемоста нет публичного API, поэтому путь файловый: запись -> расшифровка -> задачи.

## Что сделать после встречи — 3 шага

1. **Положите файл.**
   - запись встречи или голосовое: registry\intake\inbox\audio\
   - готовая расшифровка или заметки: registry\intake\inbox\text\ (обычный .txt)
2. **Запустите одну команду** (из любого каталога):

   ~~~
   powershell -NoProfile -ExecutionPolicy Bypass -File marketing-agents/registry/intake/scripts/run_intake.ps1 -Date 2026-10-31
   ~~~

3. **Посмотрите задачи**: marketing-agents\registry\tasks\2026-10.yaml
   Задачи без владельца помечены status: unassigned и продублированы в блоке
   «ТРЕБУЕТ УТОЧНЕНИЯ» в конце файла.

## Папки

| Папка | Что кладём | Форматы |
|---|---|---|
| registry\intake\inbox\audio | запись встречи, голосовое, видео | wav, mp3, m4a, ogg, opus, aac, flac, wma, mp4, mkv, webm, mov |
| registry\intake\inbox\text | готовый текст: расшифровка Телемоста, заметки, пересказ | txt, md (UTF-8) |

Если рядом с аудио лежит одноимённый .txt, он считается расшифровкой и просто переносится
в inbox\text. Если автоматическая расшифровка не удалась, рядом с аудио появится
<имя>.pending.md с объяснением и инструкциями — аудио при этом не удаляется.

## Как получить запись и расшифровку из Телемоста

1. Встреча записывается в Телемосте; после окончания запись появляется в разделе записей.
2. Если у вас включена расшифровка — откройте запись, скопируйте текст и сохраните его
   в inbox\text, например 2026-10-31-planirovka.txt. Это самый быстрый и точный путь.
3. Если расшифровки нет — скачайте запись в inbox\audio и подключите внешний ASR (ниже).

Лимиты: текст до нескольких мегабайт обрабатывается нормально (одна встреча = один файл);
ограничения на размер аудио задаёт уже внешний движок распознавания.

## Работает ли локальная расшифровка (результат разведки)

Проверено запуском на этой машине, команда:

~~~
powershell -NoProfile -ExecutionPolicy Bypass -File marketing-agents/registry/intake/scripts/transcribe.ps1 -Check
~~~

| Что проверяли | Результат |
|---|---|
| Модели DSH на диске (%USERPROFILE%\.dsh\speech-to-text\sensevoice\models) | есть: model.int8.onnx, tokens.txt, silero_vad.onnx |
| CLI/скрипт для расшифровки ФАЙЛА в DSH | **нет**: пакеты @deepseek-ai/...-speech-to-text* не имеют bin-записи, движок — host-воркер приложения, принимает только записи из браузера через внутренний loopback |
| Языки движка DSH (SenseVoice) | auto, zh, en, yue, ja, ko — **русского нет** |
| Windows Speech recognizers (файловое распознавание) | не установлены (count = 0) |
| Python-пакеты рантайма (29 шт.) | ни sherpa, ни vosk, ни whisper |
| ffmpeg | нет |

**Вывод честно: локальная расшифровка русских встреч на этой машине недоступна.** Дело не в
настройке, а в языках движка: модель DSH — zh/en/ja/ko/yue. Поэтому основной путь — готовый
текст из Телемоста, а для аудио нужен внешний движок.

## Рабочие обходы (по убыванию удобства)

1. **Расшифровка средствами Телемоста** (рекомендуется). Скачали/скопировали текст -> inbox\text
   -> run_intake.ps1. Задачи собираются из текста, аудио не требуется.
2. **Внешний ASR** — любая установленная у вас утилита, которая печатает текст в stdout:

   ~~~
   powershell -NoProfile -ExecutionPolicy Bypass -File ...\transcribe.ps1 -Command 'whisper-cli --model ggml-medium.bin --output-txt --print {file}'
   ~~~

   или разово через переменную окружения CW_ASR_COMMAND, или тем же параметром у run_intake.ps1
   (-AsrCommand). Если в команде есть {file} — подставится путь к аудио, иначе путь добавится
   последним аргументом. Пустой вывод или ненулевой код возврата = файл считается нерасшифрованным.
3. **Вручную**: пересказали главное в inbox\text\<имя>.txt -> задачи соберутся оттуда.

## Скрипты

| Файл | Что делает |
|---|---|
| scripts\transcribe.ps1 | аудио -> текст. -Check показывает разведку движка; готовая расшифровка используется как есть; иначе внешний ASR или .pending.md |
| scripts\text_to_tasks.py | текст -> задачи. Детерминированные правила, без LLM и без pip |
| scripts\run_intake.ps1 | весь цикл одной командой + отчёт: файлов, задач, что не удалось |

Полезные параметры run_intake.ps1: -Date, -InputDir, -TasksDir, -DryRun, -NoTranscribe,
-AsrCommand, -Strict (ненулевой код, если остались нерасшифрованные файлы).
Путь к python можно задать переменной окружения CW_PYTHON.

## Как текст превращается в задачи

* Задачей становится только фраза с маркером поручения: «надо», «нужно», «проверить»,
  «собрать», «подготовить», «уточнить» и т.п. Всё остальное игнорируется — задачи не выдумываются.
* Фразы с отрицанием («не надо», «не трогаем», «не срочно», «отложили») пропускаются.
* Владелец берётся из registry\agents.yaml по группе: Конкуренты -> agent-1-competitor-watch,
  Семантика/Директ -> agent-2-direct-semantics, Креативы -> agent-3-creative,
  Аналитика -> agent-4-analytics. Нет группы -> status: unassigned и блок «ТРЕБУЕТ УТОЧНЕНИЯ».
* Проект подставляется из registry\projects.yaml, если в фразе назван ЖК («Свет» -> my-zhk-svet).
* Срок понимается из простых формулировок: «до 5 ноября», «05.11.2026», «завтра», «к пятнице»,
  «до конца недели», «через 3 дня». Нет даты — поле due пустое.
* Повторный запуск не создаёт дублей: задача с таким же subject пропускается.
* Формат элемента — как в registry\README.md. Файл месяца остаётся обычным списком YAML:
  блок «ТРЕБУЕТ УТОЧНЕНИЯ» оформлен комментариями, чтобы YAML не ломался.

## Что скрипты НЕ делают

* не ходят в Телемост и не обходят капчу: публичного API у Телемоста нет;
* не устанавливают пакеты (pip/npm) и не скачивают модели;
* не придумывают задачи и владельцев: неоднозначное уходит в status: unassigned.
