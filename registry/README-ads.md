# Раздел «Реклама и кэшбэк»: трёхуровневая модель, данные, формулы

## Трёхуровневая схема (уточнена 01.11.2026)

```
ПЛАТФОРМА (ИП)
   │  деньги клиента: бюджет + вознаграждение за ведение
   ▼
ОПЕРАТОР (маркетолог или агентство) — пользователь платформы
   │  приводит своих клиентов
   ▼
КЛИЕНТ ОПЕРАТОРА (рекламодатель) — получает услугу
```

Движение денег: клиент платит платформе → часть уходит на площадки (расход),
**кэшбэк получает ОПЕРАТОР**, **комиссию за сервис оставляет платформа**.

## Оборот — это НЕ доход (защита от налоговой ошибки)

| Величина | Что это | Как считается |
|---|---|---|
| **ОБОРОТ** | чужие деньги клиентов, прошедшие через платформу | сумма прогнанных бюджетов. **Это НЕ доход платформы** |
| **КОМИССИЯ ПЛАТФОРМЫ** | доход платформы за сервис | оборот × ставка комиссии (7 % по умолчанию) |
| **КЭШБЭК ОПЕРАТОРОВ** | вознаграждение операторам | оборот клиентов оператора × его ставка (4–5 %) |
| **МАРЖА ПЛАТФОРМЫ** | что остаётся платформе | комиссия − кэшбэк операторов |

**Налоговая база считается с КОМИССИИ, а не с оборота.** Если показать оборот как доход,
получите налоговую ошибку — поэтому в интерфейсе рядом с оборотом стоит подпись
«оборот — НЕ доход платформы». Обязательная проверка в `verify-data.mjs`:
**комиссия + кэшбэк операторов ≤ оборот**.

## Роли

| Роль | Кто это | Что получает |
|---|---|---|
| Платформа (ИП) | владелец сервиса | комиссию за сервис — свой доход |
| Оператор | маркетолог или агентство, пользователь платформы | кэшбэк за ведение рекламы |
| Клиент оператора | рекламодатель (застройщик, агентство недвижимости) | саму услугу: отчёты, кампании, объявления |

## Операторы: `registry/operators.yaml`

```yaml
settings:
  platform_commission_pct: 7   # комиссия платформы, % от оборота — ДОХОД платформы
  ipo_registered: false        # пока false — агентский режим заблокирован предупреждением
operators:
  - id: op-anna
    name: "Анна Петрова"
    contact: "..."
    cashback_pct: 4            # ставка кэшбэка оператора, % от оборота его клиентов
    status: active             # active | paused
    contract: "договор №1 от 01.10.2026"
```

Связь клиента с оператором — поле `operator_id` в `clients.yaml`.
**Важно:** операторы записаны блочным форматом, а не инлайн-объектами — иначе адресная правка
по id («сменить ставку») не находит запись.

## Формулы комиссии и кэшбэка

| Показатель | Формула |
|---|---|
| Комиссия платформы | оборот × ставка комиссии (переопределение: по клиенту → по каналу → глобальная) |
| Кэшбэк оператора за период | оборот его клиентов × ставка оператора |
| Маржа платформы | комиссия − кэшбэк операторов |
| К выплате оператору | начислено − выплачено |
| Доля кэшбэка в обороте | кэшбэк оператора / оборот оператора |

## Юридическая рамка

Режим **«бюджет через сервис»** — основной: деньги проводятся через платформу, значит платформа
работает по агентской (комиссионной) схеме. НПД такую деятельность не допускает (422-ФЗ: НПД
не применяется к деятельности в интересах другого лица по договорам поручения, комиссии
и агентским). Поэтому:

- пока ИП не оформлен, в разделе горит красная плашка «до регистрации ИП этот режим использовать нельзя»;
- режим **«клиент платит площадке сам»** остаётся альтернативой — чистая услуга, НПД подходит;
- после оформления ИП кнопка «Отметить, что ИП оформлен» снимает предупреждение.

## Новые действия и отчёты

- **Начислить кэшбэк оператору** — база (оборот его клиентов) × ставка; панель считает сама.
- **Выплатить оператору** — сумма по умолчанию равна «к выплате».
- **Сменить ставку оператора** — правка `cashback_pct` в `operators.yaml`.
- **Отметить, что ИП оформлен** — снимает предупреждение по 422-ФЗ.
- **Отчёты CSV**: `/api/ads/export?what=platform|operators|channels|clients|spends|accruals`.
  Отчёт платформы начинается строкой «Оборот — НЕ доход платформы»; отчёт по операторам даёт
  оборот, комиссию, кэшбэк и к выплате по каждому.

## Данные и формулы

Раздел про прогон рекламных бюджетов и вознаграждение за ведение рекламы
(Яндекс Директ, VK Реклама, Avito, CIAN, Telegram Ads).

## Схема данных (registry/)

### `operators.yaml` — операторы платформы

```yaml
settings:
  platform_commission_pct: 7   # комиссия платформы за сервис, % от оборота — ДОХОД платформы
  ipo_registered: false        # пока false — агентский режим заблокирован предупреждением
operators:
  - id: op-anna
    name: "Анна Петрова"
    contact: "..."
    cashback_pct: 4            # ставка кэшбэка оператора, % от оборота его клиентов
    status: active             # active | paused
    contract: "договор №1 от 01.10.2026"
```

Связь клиента с оператором — поле `operator_id` в `clients.yaml`.

### Дополнение к `cashback.yaml`

- `operator_accruals` — начисления операторам: `{ id, operator, period, base_rub, rate_pct, amount_rub, status }`;
- `operator_payouts` — выплаты операторам: `{ id, operator, date, amount_rub, method, status, doc }`.

Прежние `accruals` и `payouts` (по клиентам) остались — это вознаграждение по старой,
двухуровневой схеме; новые записи ведутся по операторам.

### `ad-channels.yaml` — каналы и ставки

```yaml
settings:
  default_rate_pct: 10              # ставка по умолчанию, % от расхода
  low_balance_threshold_rub: 15000  # порог тревоги «низкий остаток»
  rounding: "до копейки, половина вверх"
channels:
  - { id: yandex-direct, name: "Яндекс Директ", status: active,
      source: api, rate_pct: 10, fixed_rub: 0, note: "..." }
```

`source` — как забираем расходы: `api` (по API), `export` (импорт выгрузки),
`manual` (только вручную). Для `export` и `manual` в интерфейсе горит пометка
«расходы вносятся вручную или импортом».

### `ad-budgets.yaml` — пополнения, расходы, ставки, режимы

Три плоских списка — их удобно дописывать из панели:

- `topups` — `{ id, client, channel, date, amount_rub, by }`;
- `spends` — `{ id, client, channel, date, amount_rub, period }`;
- `rates` — переопределения: `{ id, client, channel, rate_pct, fixed_rub, since, reason }`
  (`client: null` — для всех клиентов);
- `modes` — режим работы: **берётся последняя запись**, история сохраняется.

### `cashback.yaml` — начисления и выплаты

- `accruals` — `{ id, client, channel, period, base_rub, rate_pct, fixed_rub, amount_rub, status, doc }`;
- `payouts` — `{ id, client, date, amount_rub, method, status, doc }`.

## Формулы

| Показатель | Формула |
|---|---|
| Остаток бюджета (по клиенту и каналу) | пополнения − расходы |
| Кэшбэк за период | **база × ставка / 100 + фикс** |
| Эффективная ставка клиента | начисленный кэшбэк / расход |
| Средняя ставка по разделу | весь кэшбэк / весь расход × 100 |
| Доля канала | расход канала / общий расход |
| К выплате | начислено − выплачено (со статусом «выплачено») |

Ставка применяется так: переопределение по клиенту и каналу → ставка канала → глобальная
по умолчанию из `ad-channels.yaml`.

Скругление — до копейки, половина вверх. Расхождение хотя бы на копейку ловится
проверкой в `verify-data.mjs` и красной тревогой прямо в разделе.

## Два режима — юридически важно

| Режим | Что происходит | Налоги |
|---|---|---|
| `client-pays` — **клиент платит площадке сам** | деньги идут от клиента прямо на площадку, мы выставляем вознаграждение за ведение рекламы | **Чистая услуга, НПД подходит** |
| `through-service` — **бюджет через сервис** | деньги клиента приходят нам, мы оплачиваем площадки, себе оставляем вознаграждение | **Агентская (комиссионная) схема. По 422-ФЗ НПД НЕ применяется** — нужно ИП или ООО; при НПД выставляем вознаграждение за ведение |

Оба режима видны в интерфейсе переключателем, у агентской схемы горит жёлтая плашка,
а при переключении панель спрашивает подтверждение с тем же предупреждением.
Мы не прячем риск: пользователь видит его до нажатия.

## Действия в разделе

1. **Зафиксировать пополнение** — клиент, канал, дата, сумма.
2. **Зафиксировать расход** — клиент, канал, дата, сумма, период.
3. **Импорт выгрузки (CSV)** — формат строки: `client;channel;date;amount;period`.
   Полезно там, где у площадки нет API (Avito, CIAN).
4. **Задать/изменить ставку** — по клиенту и каналу, с причиной и датой; история в `rates`.
5. **Начислить кэшбэк** — база и ставка; панель показывает формулу до нажатия и считает сумму сама.
6. **Зафиксировать выплату** — клиент, дата, сумма, способ.
7. **Выгрузка CSV** — расходы, по каналам, по клиентам, начисления (`/api/ads/export?what=...`).
8. **Сменить режим работы** — с юридическим предупреждением.

Каждое действие пишет файл **атомарно** (temp + rename) с копией `.bak-<timestamp>`;
откат из копии возвращает файл байт-в-байт (проверено по SHA-256 для всех действий).

## Тревоги

- **Низкий остаток** — остаток клиента ниже порога из `ad-channels.yaml`. Уровень
  `critical`, если остаток ушёл в ноль или ниже.
- **Агентская схема** — информационная плашка по клиентам с режимом `through-service`.
- **Начисление не сходится с формулой** — критично, с указанием файла и суммы.

3 клиента, 5 каналов, 6 пополнений, 12 расходов, 6 начислений, 2 выплаты.

# Кошелёк и кэшбэк с любого оборота (модель click.ru)

## Единый кошелёк клиента

```
пополнение -> расход по площадкам -> ВОЗВРАТ от площадки -> кэшбэк оператору
                                              │
                                              └─ из него же берётся маржа платформы
```

| Величина | Формула | Где в панели |
|---|---|---|
| Пополнено | сумма `topups` | кошелёк, KPI «Пополнено» |
| Израсходовано | сумма `spends` | KPI «Израсходовано» |
| Остаток | пополнено − израсходовано | KPI-подпись кошелька |
| **Возврат от площадки** | сумма `returns` (ФАКТ), ожидаемый = расход × `return_pct` канала | блок «Возвраты от площадок» |
| **Кэшбэк оператора** | оборот клиента × ставка оператора (`operators.cashback_pct`) | блок по операторам |
| Кэшбэк, покрытый возвратом | **min(кэшбэк, возврат)** | предохранитель |
| Комиссия платформы | оборот × ставка комиссии | KPI «Комиссия» |
| Маржа платформы | возврат − кэшбэк + комиссия | KPI «Маржа» |

**Кэшбэк считается ОТ ВОЗВРАТА.** Площадка возвращает нам агентское вознаграждение
(`return_pct` по каналу, факт — в `returns`), и именно из него платится кэшбэк оператору.
Если возврата нет (нет партнёрского договора), платить кэшбэк нечем — это убыток платформы.

## Предохранитель от убытка

Красное предупреждение в разделе и критическая тревога, если по клиенту
**кэшбэк оператору больше возврата площадки**:

```
убыток = max(0, кэшбэк к выплате − возврат от площадки)
```

Демо-пример в данных: клиент «Пример: убыточный клиент» — оборот 120 000 ₽ на CIAN,
ставка оператора 6 % → кэшбэк 7 200 ₽, партнёрского договора нет → возврат 0 ₽ →
**убыток 7 200 ₽**. Предупреждение показывает: «На этом клиенте вы теряете 7 200 ₽ своих денег».
Проверяется в `verify-data.mjs` отдельной проверкой.

## Чем отличаемся от click.ru

| click.ru | Мы |
|---|---|
| Возврат «до 22 % при соблюдении условий партнёрской программы» | **кэшбэк с любого оборота, без минимального порога**; ставки в панели — наши фактические по договорам |
| Бонус 15 % от первого пополнения, SEO бесплатно от 50 000 ₽ | порогов нет: считаем с первого рубля оборота |
| Отсрочка до 50 дней | отсрочка как **учёт** дней и напоминание (финансирование не реализовано) |
| Один счёт и общий акт | единый кошелёк клиента и общий акт по всем площадкам за период |

## Отсрочка платежа

Список `deferred` в `ad-budgets.yaml`: `{ client, days, since, note }`. Панель считает срок
оплаты (дата + дней), показывает «в срок / скоро срок / просрочено» и создаёт напоминание,
когда до срока ≤ 14 дней. Финансирования нет — только учёт.
