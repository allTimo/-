# Модель данных сервиса

Источник правды для разделов «Клиенты», «Подписки», «Услуги», «Очередь работ» и «Экономика».
Правки из панели атомарные (temp + rename), с копией `.bak-<timestamp>`; обратимость проверяется по SHA-256.

## clients.yaml — клиенты

| Поле | Что значит |
|---|---|
| `id` | латиница с дефисами, уникальный |
| `name` | название клиента |
| `contact` | контактное лицо |
| `status` | `lead` (лид) · `active` (активен) · `paused` (на паузе) · `churned` (ушёл) |
| `plan` | тариф: `start` · `business` · `premium` |
| `since` | дата подключения |
| `objects` | id объектов (ЖК) из `projects.yaml` |
| `services` | id подключённых услуг из `services.yaml` |
| `note` | свободная заметка |

## services.yaml — каталог услуг

| Поле | Что значит |
|---|---|
| `id`, `name`, `what` | идентификатор, название, что делает агент |
| `agent` | id агента-исполнителя из `agents.yaml` |
| `schedule` | расписание, например `weekly:monday:10:00` или `on-demand` |
| `artifacts` | что получает клиент |
| `cost_rub` | себестоимость одного прогона, ₽ |
| `price_rub` | цена клиенту за период, ₽ |
| `status` | `active` · `planned` · `paused` |
| `enabled` | тумблер: услугу можно запускать |

**Маржа** = `price_rub − cost_rub`; в процентах — от цены.

## subscriptions.yaml — подписки

`client`, `service`, `plan`, `period`, `start`, `end`, `status` (`active` / `paused` / `overdue` / `closed`), `price_rub`, `invoiced` (счёт выставлен).

## runs.jsonl — журнал прогонов

Дописывается по одному JSON на строку, ничего не перезаписывается:

```json
{"run_id":"run-...","ts":"2026-10-31T10:00:00+03:00","service":"competitor-watch","client":"client-svet","agent":"agent-1-competitor-watch","status":"ok","duration_ms":1234,"cost_rub":120,"artifact":"...","error":null}
```

`status`: `ok` · `partial` · `failed`. Повторный прогон просто добавляет новую строку — счёт не дублируется.

## invoices.yaml — счета

`id`, `client`, `period`, `amount_rub`, `status` (`draft` / `issued` / `paid`), `issued`, `file`.

## results.yaml — финальные результаты и отправка

| Поле | Что значит |
|---|---|
| `id`, `title`, `summary` | идентификатор, название, что сделано одной фразой |
| `client`, `project` | id клиента и проекта (могут быть пустыми) |
| `period` | за какой период результат |
| `agent`, `service` | id агента-исполнителя и услуги |
| `created` | когда результат готов (ISO) |
| `artifacts` | список файлов результата (пути от корня `marketing-agents`) |
| `sent_channel` | `telegram` · `vk` · `whatsapp` · `email` · `link` · `download` · `none` |
| `sent_to` | куда именно: канал, чат или адрес — **правится в панели** |
| `sent_at` | когда отправлено (ISO) или пусто |
| `sent_status` | `отправлено` · `ожидает` · `ошибка` · `не отправлялось` |

В MVP отправка выполняется **вручную** (или агентом по команде): панель хранит и показывает факт
отправки, но сама сообщения не рассылает. Перечисления (`sent_channel`, `sent_status`) пишутся
без кавычек — так обратное переключение возвращает файл байт-в-байт.

## Как считается экономика

- **Доход** — сумма цен активных и просроченных подписок.
- **Себестоимость факта** — сумма `cost_rub` из журнала прогонов.
- **Себестоимость плана** — сколько прогонов ожидается по подпискам, умноженное на себестоимость услуги.
- **Маржа** = доход − себестоимость; считается и по услуге, и по клиенту.
- Модель без цены в `registry/prices.yaml` помечается «цена неизвестна» — рубли по ней не начисляются.
