# Тонкие настройки агентов

Каждый агент настраивается ОТДЕЛЬНЫМ файлом: `registry/agent-settings/<agent-id>.yaml`.
Это «основная настройка»: кроме общего тумблера включения у агента есть расписание, лимиты,
отчёт, доставка, алерты и ограничения. Правка из панели — атомарная, с копией `.bak-<timestamp>`;
обратимость проверяется по SHA-256, у каждого поля есть «вернуть как было».

## Общие группы (есть у всех агентов)

| Группа | Поля | Смысл |
|---|---|---|
| `schedule` | `enabled`, `days` (ISO 1–7), `time`, `frequency` (`daily`/`weekly`/`monthly`/`on-demand`), `timezone`, `only_on_new_data` | когда агент запускается сам |
| `model` | `name`, `limit_rub`, `limit_tokens`, `on_limit` (`pause`/`stop`/`warn`) | на какой модели работает и сколько ей позволено тратить |
| `priority` | `level` (`low`/`normal`/`high`), `max_parallel`, `timeout_sec`, `retries` | очередь, параллельность, таймаут, повторы |
| `report` | `formats` (`md`/`xlsx`/`csv`/`pdf`), `sections`, `language`, `branding` | что и на каком языке получается на выходе |
| `delivery` | `channels` (`telegram`/`email`/`vk`/`link`), `addresses`, `auto_send`, `copy_to` | куда отправлять и автоматически ли |
| `alerts` | `when` (`never`/`fail`/`low_data`/`always`), `price_threshold_pct`, `quiet_hours` | когда беспокоить и в какие часы молчать |
| `limits` | `skip_weekends`, `min_interval_hours`, `stop_switch` | «не запускать в выходные», «не чаще N часов», стоп-кран |

## Специфичные группы

### Источники: ОДИН источник правды

Решено 01.11.2026 — источники больше не живут в трёх местах:

| Где | Что задаёт | Кто главный |
|---|---|---|
| `01-competitor-watch/config/clients/<client-id>.yaml` | что **реально включено для конкретного клиента** | **ГЛАВНЫЙ источник правды** |
| `agent1.watch.sources` (в этом файле) | значения по умолчанию для **автоподбора конкурентов** | вспомогательный |
| ~~`agent1.sources`~~ | **УДАЛЁН** — дублировал и расходился | — |

Подтверждённые конкуренты **не хранятся** в настройках агента: они живут в клиентских
конфигах (`config/clients/<client-id>.yaml`, поле `competitors`). Заглушки из настроек убраны.

### `agent1.source_modes` — режим сбора по источнику

Единственное место, где задаётся доступность и способ сбора. Значения:
`http` (обычный запрос без логина) · `browser` (Chrome без логина) · `off` (выключен).

| Источник | Режим | Факт (проверено 01.11.2026) |
|---|---|---|
| `cian` | **http** | работает обычным HTTP без логина: 200 и реальные цены |
| `avito` | **browser** | работает через браузер без логина: движок взял 50 лотов |
| `yandex-realty` | **http** | требует ссылок уровня проекта — включаем с пометкой |
| `domclick` | **off** | закрыт (401/403) — держим выключенным |
| `developer-sites` | **http** | сайты застройщиков, обычный HTTP |

### `agent1` — у Агента 1 (мониторинг конкурентов)

| Поле | Смысл |
|---|---|
| `projects` | проекты клиента (id из `registry/projects.yaml`) |
| `competitors` | список конкурентов со ссылками: `{ name, url }` |
| ~~`sources`~~ | **удалено**: дублировало источники. Что включено для клиента — в клиентском конфиге; режим сбора — в `agent1.source_modes` |
| `source_modes` | режим сбора по источнику: http / browser / off (см. таблицу выше) |
| `price_threshold_pct` | порог изменения цены, % — ниже него изменение не считается значимым |
| `min_lots` | минимум лотов, иначе данные считаются неполными |
| `promo_words` | словарь акций для поиска промо в текстах |
| `collect_mode` | `http` — без браузера, `browser` — через Chrome без логина |
| `compare_depth_weeks` | на сколько недель назад сравнивать |

### `source_agent` — у агентов-источников

`rate_limit_per_min` (запросов в минуту), `pause_ms` (пауза между запросами),
`max_pages` (максимум страниц), `timeout_sec`, `stop_on_block` (остановиться при блокировке),
`use_browser` (использовать ли браузер).

## Файл-заготовка

Если у агента `status: stub`, поля показываются, но **неактивны и сохранять их нельзя** —
так у Агента 2, 3 и 4: «настройки появятся вместе с агентом».

## Проверки

`verify-data.mjs` проверяет: настройки читаются, значения в допустимых диапазонах
(часы, дни недели, неотрицательные лимиты), у каждого агента из `agents.yaml` есть свой файл,
а эффективные настройки совпадают с содержимым файла. Обратимость правки — по SHA-256.
